## Owner-readable summary

A transaction/client supplies bounded paths to an epoch's anchor set; a pure verifier checks them against **canonical current live edges**, not an indexer's assertions. The snapshot fixes the difficulty and anchor membership, not current edge liveness. Search, trees, caches and routing may be wrong or unavailable without making a bad witness pass. Anchors are routing targets, **not Council members or additional governance powers**. D41's qualifying-guarantee authorization still precedes invitation burn/recording; a path witness does not replace it, own-source funding or the contest window.

The requested reference uses D distinct terminal anchors from an epoch top-A set, A/D2 or3, plus bounded slack. It compares anchor→subject directed trust with an explicit undirected projection. Default candidates are hop limit5, grace1 epoch, slack1, weekly epochs, rotation fraction0.15, pool12/uniform; all are placeholders. Snapshot/count/eligibility/ranking inputs need a declared public verification process, never evaluator personhood/ownership truth. Own-days Standing is not implemented or interchangeable with repo XP: its proposed default versus D35's selected XP-core meaning needs owner clarification before ranking/enforcement, not an invented conversion.

The per-user gate certifies connectivity only. Different subjects can reuse the same bridges in separate witnesses; e>=D raw attack edges alone is not sufficient if those edges share bottlenecks or cannot reach D distinct anchors inside the hop bound. Conversely, an explicit sufficiently connected cluster may give every member a valid witness. Neither topology nor indexer success verifies people, usefulness, independent operators or actual funded attack feasibility.

A separate **opt-in research** capacity layer compares G/G+C/C. Its literal all-node unit-capacity formulation caps source injection through unit-capacity anchors at A; if every accepted target consumes D units, A/D bounds throughput and a unit-capacity target cannot receive D>1. This must be resolved, not hidden by silently exempting anchors/targets or relabeled a selected quota. D35's default no-cluster-quota rule remains unchanged.

M0 records contracts/risks before code. M1 can verify supplied, explicitly qualified snapshot fixtures without choosing a live verification/Standing/epoch-transition process. Later dependent milestones remain gated by those choices. No E1–E8 research registration/result, benchmark curve or SAFE parameter range exists.

## Pure verifier and StateAccessor contract

The semantic witness is exactly `{subject, epoch, paths}` with paths `[subject,...,anchor]`. The application supplies an **expected subject** and trusted policy/state context; a witness may not choose its own direction, difficulty, resource envelope or deployment. Proposed narrow synchronous accessor capabilities are:

```text
state identity/current epoch
snapshot(epoch) -> declared D_epoch, anchor membership commitment, policy/metric identity
current canonical directed edge liveness (and optional relation identity)
current emergency-removal status
subject degree upper bound for the chosen projection (or explicit unknown)
optional declared intermediate standing only when s_min is enabled
```

The implemented synchronous supplied port is fixed in M1-B and provided by M2-A immutable captures: view/snapshot/anchor/removed/edge/degree/anchorCount and optional enabled standing; degree/eligible-anchor counts return explicit null when unknown. The Native adapter is a read-only named diagnostic active/accepted-reference capture, not authenticated canonical state, final duty/slash semantics, a fresh-at-use Model authorization or a shipped chain API. A view must be coherent/frozen for the whole verification; no network call, mutation, random draw, search service or cached indexer response belongs here. An accessor returning arbitrary booleans is **not** authenticated canonical state. Tests may use labeled supplied graphs; a chain/client adapter later needs accepted storage or independently checked edge/membership/state proofs, availability and root/policy binding. Merkle-root possession alone authenticates neither its publisher nor membership in real protocol state.

### Acceptance interpretation and bounds

- **Context/epoch:** require the expected subject, existing snapshot and current-g<=epoch<=current under trusted bounded policy. Snapshot D must be positive and inside trusted implementation limits; N=0 still has D33's numeric target1, not an empty-witness exemption. Bounds cover total bytes, ID bytes, epoch integers, max D, k<=D+s_max and every path<=r edges **before** unbounded allocation/lookups. Oversize/noncanonical transport fails as a whole.
- **Individual candidates:** positive-length simple paths start at the expected subject, end at a nonremoved snapshot anchor, use existing current-live edges in the declared projection and satisfy optional s_min only when enabled. A zero-hop subject/anchor path counts nothing. Malformed wire/schema is not slack. A well-formed path that has become dead, stale or ineligible can fail individually; enough remaining candidates must survive.
- **Counted family:** at least D candidate paths must be simultaneously valid, end at D distinct anchors and share **only the subject**. An anchor used as one path's endpoint cannot also be a shared transit vertex on another counted path. No blanket ban on an unshared anchor transit vertex is inferred from the old study's unselected terminal-only convention. Duplicate paths give no extra support.
- **Slack selection:** the literal threshold is existence of a compatible D-subfamily, not greedy counting in input order. Regression: an early candidate can intersect each of two later mutually disjoint candidates; a first-fit algorithm must not falsely reject that sufficient subset. Canonical path order must not change this decision. A stricter all-submitted-disjoint contract would be a different acceptance rule and needs an explicit owner change, not an implementation shortcut.
- **Cost:** memoized edge/vertex/member accesses can be O(k*r); exact compatible-subfamily CPU is a separate obligation. General slack may require bounded subset/conflict search. Do not advertise linear total CPU merely because storage lookups are linear. The s_max1 candidate permits a specially proved bounded-slack implementation; supported ranges/CPU/byte limits must be explicit before M1 code, with no silent generalization.
- **Self eligibility:** default anchor candidates need D paths to other anchors; subject membership supplies no path to itself. If the requested exemption arm is enabled later, report a distinct authorization exemption, **not** a certificate of D paths that violates I1. It grants no governance authority.
- **Emergency:** a currently authorized emergency removal takes effect even for an otherwise in-grace snapshot/witness. The verifier consumes that canonical decision; it never infers proven guilt from topology or an allegation.

I1–I7 acceptance requirements now have M1 bounded supplied-view test evidence (not live-state authentication or universal proof): I1 counted-family soundness; I2 deterministic/bounded decisions and counted access/CPU work; I3 independence from indexer/cache state; I4 intermediate-score invariance with s_min off; I5 immediate removal; I6 canonical subject/epoch/context binding; I7 explicit degree/anchor-shortage infeasibility diagnostics. Vectors cover every individual failure, shared trunks, cross-path endpoint/transit reuse, duplicate endpoints/paths, invalid slack before/after valid candidates, malformed object and wire inputs, limits, grace, self cases, wrong policy/subject, emergency revocation and direction.

## Direction, degree and epoch semantics

For `directed-from-anchor`, stored guarantees mean voucher→subject. A witness is written subject-first, so adjacent `[x,y]` requires a **live y→x edge**. The number of disjoint paths to U is at most U's distinct live incoming-neighbor count, further bounded by eligible distinct anchors excluding U. If D exceeds this bound, report `degree-infeasible`/anchor shortage, not an unexplained search miss. D<=degree is necessary, not sufficient under bottlenecks/hop limits. Maintained canonical degree summaries are needed for bounded verification; missing metadata is unknown, not a made-up count.

The requested `undirected` arm treats direction as a graph projection, not new consent: **any-live-orientation versus reciprocal-only qualification must be named explicitly**. This affects the degree upper bound and liveness checks. The owner requests both directed and undirected runs, not a universal selected direction. No ordinary directed guarantee is silently duplicated in Model history.

An epoch snapshot binds its adopted D, eligible anchor set/root, metric/ties/policy identity and activation. Exact top-A selection versus hysteresis/rotation-capped retention must distinguish candidate rank from retained membership; they cannot both be assumed automatically when ranks change. Do not use the instantaneous formula target as an already adopted threshold. Old-snapshot grace plus current guarantee authorization can otherwise mix two difficulties: common applicable epoch/value, pending/in-flight boundary treatment and rollback/reorg/finality need an explicit contract before economic integration. No automatic identity invalidation at a transition. Existing edge-ID proofs invalidate remove/re-add; the requested vertex-only witness instead tests current liveness unless relation identity is added by an explicit new version. This is not historical-liability erasure.

Requested parameter candidates (all placeholder values, not calibration): directions both; anchor_metric own-days Standing (proposed default) versus repo XP; A/D2(default)/3; M4/8/12(default)/16; uniform(default) versus best-of-two load; r4/5(default)/6; grace1(default, candidate1–2); slack1; rho0.15; epoch7d; s_min off; anchor_self needs-other-paths(default) versus exempt; emergency on authorized proven violation; difficulty from snapshot. s_max, hard byte/D limits, hysteresis R_in<R_out values, tie order, rounding/minimum rotation, eligible-pool shortage and emergency rotation exceptions are not numerically bound. Pool load is an advisory workload statistic, not global admission capacity or verified independence.

The requested query pipeline is bounded bidirectional exploration from U toward the anchor-tree union, diversified pool/branch routing, a candidate unit-vertex-split solve on ball(U) plus retained trees for D+1 paths, and full ref2 verification before return. The requested classical per-epoch Even–Shiloach-style decremental strategy remains distinct from the implemented bounded mixed-change path-label reference. C4 implements only bounded two-sided edge extraction plus retained-subgraph M2; the requested production unit-split/D+1 pipeline remains an implementation target, not an established completeness or scaling bound. The hop/subgraph conditions below still apply.

Cached whole paths cannot be spliced without full simple/disjoint/endpoint/live checks. [Requested-epoch binding](../studies/2026-10-26-witness-indexer/m3-cache-epoch.md) also requires decoded witness.epoch===query.epoch: a packet may validly verify in another grace snapshot yet not answer this request. A mismatched hint/cached candidate rejects normally before retention/return and uses the existing bounded requested-epoch fallback; packet verification alone cannot justify changing query D/epoch, and this fixes no live authorization/adopted-D choice. Segments need edge identity/version, verification time, TTL/usage and current liveness rechecks; unknown/expired cache entries do not make a live edge true. Staggered TTLs/routes reduce synchronized repairs, not canonical emergency enforcement. Removal marks affected witnesses stale; repair may reroute/extend through currently authorized live edges only, and must reverify the complete witness. A removed anchor can be an intermediate only if the edge/standing policy still permits it; removal does not create a replacement path or erase a selected duty.

Every returned candidate is locally checked by ref2 and checked again by the consequential verifier against independent canonical state. Cache poisoning, wrong roots, selectively omitted edges, lying search statuses and stale live bits must never create false acceptance. Client fallback can use other indexers or local public snapshots with authenticated edges; publishing a deterministic fallback is a liveness mitigation, not a personhood oracle.

**Completeness traps:** ordinary vertex-split max-flow does not enforce a path-hop bound by itself. A layered graph must not duplicate a person's capacity across hop layers. A single BFS parent/tree or a pruned ball∪trees subgraph can omit alternatives needed for disjointness. “Exact within retained subgraph” is not complete for the public hop-bounded problem. M2 needs an exact bounded-hop reference checked against brute force; M3 reports misses/budget exhaustion versus that oracle before performance. No search budget can turn unknown into certified infeasibility. Certificate soundness proves a positive lower bound, not a maximum or negative result.

**Maintenance target:** per-anchor O(m*r) decremental BFS is conditional on a fixed-epoch deletion model, not arbitrary repeated insert/delete churn at cost independent of update count. Record insertions, deletions, resets/rebuilds, A, m, r and query traffic separately. Do not claim O(A*m*r) total or unit-network Dinic O(E*sqrt(V)) without the exact transformed-network/update assumptions and measured machine/graph/workload evidence. Wall time, lookup/hash work, memory and rebuild/fallback work are distinct.

## Capacity layer: unresolved flow contract, not selected quota

G certifies the local path condition; C applies an epoch-batch feasible allocation; G+C requires both **after C is defined**. The proposed super-source/anchor/unit-split network needs explicit source capacities, transit versus terminal exemptions, per-target demand, all-or-none acceptance, sink construction, accepted-set selection/ties/fairness, reset/reuse periods, captured-anchor injections and scarce-pool behavior. Plain maximum total flow need not maximize fully satisfied multi-unit target demands.

Under the **literal** unit cap on every anchor, source flow<=A. With unit target cap, target flow<=1. Thus D>1 target demand is infeasible and D-unit acceptance would also force acceptedCount<=floor(A/D), before any attack. This is an analytic consequence of the proposed capacities, **not an experiment/kill result**. Changing it by unlimited anchor supply, endpoint exemptions or per-candidate separate flow is a different capacity contract; do not choose silently. Endogenous verified/personhood supply is still not proven.

Only a specified feasible allocation can support a cut-bound argument. If each accepted fake consumes q units that actually cross an authenticated honest/coalition cut of total capacity e, and there is no captured-anchor/initial injection behind it, then q*acceptedFakes<=e for that batch. q, e and cut membership must be declared; captured anchors, genuine paid people, seeding and reuse across epochs change the statement. Evaluation ownership stays outside defense state. No inference from raw edge count alone or lifetime amplification claim is licensed.

A root of accepted-set/flow leaves is not by itself a fraud proof. Local O(deg) capacity/conservation checks require authenticated canonical incident edges, unique accounting, source/sink demand, accepted-set consistency and data availability. Omitted/duplicated edges, inconsistent split copies, invented sources/flows and unavailable leaves need adversarial vectors; Merkle proofs/hash work count too. Feasibility is safety, not maximality/fairness: a feasible censoring allocation can exclude honest targets. Keep that liveness/DoS loss visible.

## Threat model, privacy and runbook boundary

Safety assumes canonical authenticated state, immutable verification context and a sound bounded codec/verifier—not indexer honesty. Liveness threats are censorship, selective service, throttling, fabricated no-path results, query-triggered overload, cache poisoning/TTL herds, anchor capture/key purchase and targeted emergency repair. Mitigations are multiple independently operated indexers, published bounded local computation, failure/budget telemetry and recomputation against public data. Multiple URLs/keys do not prove independent operators.

The base vouch graph is public in this direction; indexers additionally learn subject-query times, repeat attempts, IP/client associations and requested epochs/routes. No privacy claim follows from TLS, segment caches or Merkle roots. Minimize/declare logs, access/retention and disclosure before any public HTTP/pilot. §46.11 external-application privacy proofs remain OPEN/out of scope; no face/personal data or real graph download is authorized by this document.
