# Simulator contract

The simulator is one Rust crate, [`simulator/`](../simulator), standard library only (D130). It replaced the Node.js simulator; that implementation, its tests and its raw results are preserved only at the git tag `legacy-node`. This page owns what is implemented, the declared deviations from the [protocol](facety.protocol.en.md), every simulation assumption, and how the baseline was validated. Protocol meaning lives in the protocol; decisions in the [decision log](decisions.en.md); findings in the [insight register](insights.en.md); open work in [BACKLOG](../BACKLOG.md).

## Layout and use

| Module | Owns |
| --- | --- |
| `graph.rs` | directed graph with sorted adjacency lists, revision counter |
| `rng.rs` | decision-keyed randomness (policy `facety-sim-rng/v1`) |
| `paths.rs` | layered support (D124), exact length-bounded internally vertex-disjoint paths (D36/D123) with an independent verifier |
| `json.rs` | escaping and a strict validator, so saved results are always valid JSON |
| `world.rs` | accounts, Self-ID acts and XP, owned valences and K slots, special invitation links, disputes as activity holds, the Council-path gate |
| `runner.rs` | the takeover runner: honest behavior, attacker strategies, detection |
| `main.rs` | `facety-sim grown`: for each seed grow an honest network to a size (without detection), then run the attack phase from that snapshot with detection on; optional phases (error burst) and plots |

```text
cargo test --release                     # unit tests, parity tests, documentation integrity
cargo run --release -- grown --seeds 4 --attackers 10 --horizon 60     # baseline rules
```

`grown` flags: `--seeds`, `--first-seed`, `--bound N|none`, `--no-layered` (ablation of D124, which is on in the baseline), `--allow-disputed` (ablation of D131), `--exclude-challengers` (ablation of D157), `--attackers`, `--horizon`, `--target-honest`, `--strategy cone|honest-first|supported-first`, honest levers (`--vetting`, `--vet-sens`, `--vet-fpr`, `--met`, `--double`, `--artifact`, `--collusion`, `--subtree-cases`, `--confirm`, `--confirm-public`, `--targets-only`, `--svg DIR` (one plot per seed), `--accuse`, `--accuse-hubs`, `--key-loss`, `--recovery-vouch`, `--recovery-delay`, `--befriend`, `--invite`, `--accept-far`, `--odd-share`, `--odd-mult`, `--shock-day`, `--shock-days`, `--shock-fpr-x`, `--appeal`, `--restore-links`, `--recover-liquid`, `--xp-penalty`), detection levers (`--inspect`, `--fpr`, `--sens`, `--review`, `--accuracy`, `--public-look`, `--acquit`, `--detect-prefix`), `--council-seats`, `--council-seats-per-d`, `--council-per-thousand`, `--max-d`, `--k`, `--k-step`, `--k-xp-per-level`, `--search-order`, `--careless`, `--corrupt`, `--careless-accept`, `--patience`, `--defense`, `--defense-days`, `--base-stake`, `--no-stakes`, `--no-halving`, `--halving-spares-council`, `--join-rate`, `--council-rate`, `--council-turnout`, `--no-attacker-ladder`, `--disputes-from`, `--honest-genesis`, `--max-subjects`, `--threads`, `--out DIR`, `--prefix-only`. Output is one JSON line per seed, printed as each seed finishes (order by completion; sort by the `seed` field). Unknown or repeated options, missing values and invalid parameters (probabilities outside [0, 1] or not finite, zero seeds, threads or horizon, a path bound outside 2..32, layered support without a bound, a target below the genesis size) are refused with `error: ...` and exit code 2; nothing runs and nothing is saved.

With `--out DIR` each seed writes `DIR/<seed>-<configuration digest>.json` containing `meta` (build commit and whether the tree was dirty when built, elapsed seconds, threads, command line) and `result` (schema `facety-sim/result-v2`, engine, randomness policy, the initial configuration, every later phase with its day and complete configuration, the effective configuration, completed days, the reason the run stopped or was censored, counters, the daily history). The growing phase and the attack phase keep separate configurations. The digest covers seed, initial configuration and phases, so the same seed with different settings never shares a file. A file that already exists is never overwritten silently: the run reports the conflict and exits with code 3 unless `--overwrite` is given. `tests/cli.rs` guards the command line and the saved files; the result section is byte-identical for identical runs.

## Randomness

Every decision draws from its own stream keyed by (root seed, channel, actor, day), so unrelated decisions never share a stream offset. Generator: splitmix64 seeding into xoshiro256**. The identifier `facety-sim-rng/v1` replaces the retired `sha256-xoshiro128starstar-v2`; results are statistically comparable with the retired simulator, not bit-identical. A new key layout or generator needs a new identifier. A snapshot is a clone of the whole simulation state (`Sim: Clone`), so many attack variants start from one grown network without replaying its history.

## Deviations and assumptions

- XP follows D42/D54/D163: a valid, uncancelled Self-ID credits its author and its creation-time guarantor snapshot at `recorded_at + 24h`, whatever happens to the entitlement; time moves only through `tick`, which settles every act that matured up to the new hour before any decision reads XP, so settling a batch equals processing chronologically (credits at an hour apply before the other events of that hour). The credit stamp is the maturity time. The old convention (credit when the source right is spent) is retired; it survives only as the reproducible tag `baseline-spend-credit-d156`, and results of both are not comparable.
- Matured XP is revoked only by a separately authorized correction: a chain cut (`void_chain`, the verdict path), `revoke_source_xp`, or the D9 revocation of the ending party's guarantor receipts when a guarantee ends (already credited receipts only; a guarantor who leaves before an act matures stays in that act's snapshot, D54). Cancelling an invitation in its freeze no longer revokes the source XP (D163). The D55 per-act snapshot of the losing act is still not kept: `penalize_xp` halves the current balance, which now includes every credit matured up to that moment and nothing later.
- Free cancellation (`cancel_self_id`, D42/D79): author or a guarantor of the snapshot, only while the act is unspent and younger than 24 hours, refused for a disputed author (the precedence of dispute freeze and cancellation is OPEN, the smallest reading is taken); the backing is burned, no XP is ever earned, the rolling 24-hour slot stays used. The runner does not exercise it yet (the freeze veto of invitations is a separate operation).
- The Council, the active count and difficulty D, the layered-support levels and the distance pruning are refreshed once per simulated day, not on every call. An account created today is therefore not seen by today's distance pruning.
- Council ties break by account index (older first).
- No Collector market, stakes, fines, debt or Treasury: conversion only turns a right into liquid money so that dirty-FACY share can be measured.
- Disputes follow the ladder of D158, D159, D161 and D162 (`chekharda.rs`, `World::begin_case`, `join_case`, `council_join`, `settle_case`): position 1 reserves the base stake from spendable liquid FACY, every admitted position has its own window and extends the shared deadline, an entry at the deadline hour is refused (a simulation convention, OPEN in the protocol), same-hour entries apply in submission order, the Council is one terminal position without stake or XP condition and its ballots do not move the clock; settlement pays each winner the stake of the position below (whole FACY, `ceil(7 * 1.2^(n-1))`: 7, 9, 11, 13, 15, 18, 21, 26), burns the stake of a losing top position and any stake that would go to a Council entry (no recipient is selected, D64), halves the XP of losing participants (the cut is the floor of half, so the rest is the larger half), and when the accused loses charges the base stake to the accused (paid to the accuser) and to each of the accused's mutual guarantors at opening (burned); what cannot be collected from spendable liquid FACY becomes recorded debt, never collected later (a declared deviation: no Treasury, no debt service, no emission-balance accounting; the stake backing is exclusive custody of liquid FACY, one of the OPEN backing choices). Each participant, the accused included, is held (D77) until the case ends; holds from several cases add up and release only with the last. The accused's unspent rights are not frozen (§17.4 is not modeled); a Council entry's participation hold covers the entering member only. Who joins and when is a set of declared research assumptions (see the lever table), the verdict is the ladder's (last unopposed side, or the Council's equal-vote majority, or the accused's accepted proof of reality) and no longer a noisy draw; the declared accuracy now enters only through the beliefs of supporters and Council members. Evaluator ground truth stays outside the world: it reaches the ladder only through those beliefs. The free cancellation of an immature Self-ID by a guarantor (the freeze veto) is a separate operation and does not pass the XP gate.
- Evaluator labels (cohort and identity kind) are read only by the observation functions of noisy looks and verdicts; the world never sees them.
- Fake accounts cost nothing beyond protocol FACY (an upper bound on attacker ease). Attacker operators are real people; only cone accounts and double-life accounts are false identities.
- Honest behavior rates, detection parameters and the 28-day activity window are scenario assumptions, not calibrated human behavior. Raw reports of attack outcomes are conditional on scenario, policy, horizon, seeds and the success criterion (D129).
- Detection is always on (D125); the retired no-detection arms are not reproduced.

## Benchmark panels for default-rule changes

The baseline is still being formed: defaults and rules change (the emission path check D156 was the latest). Every change of a default or of a rule reading is therefore tested with the same panels, so that the effect is measured and not guessed. The panels use the `grown` runner as it is; a change keeps an ablation flag for the previous reading (a result is reproducible only with the settings it records), and the effect is measured paired, new against old, on the same seeds.

| Panel | Purpose | Content | Seeds | When |
| --- | --- | --- | --- | --- |
| 0 Regression | nothing broke, efficiency changes keep outcomes | `cargo test --release`; for an efficiency change (D145) the saved result files of three fixed configurations must compare equal before and after | seeds 1 and 2 | every change |
