# Simulator model and research contract

This document owns the implemented simulation semantics. The [protocol](facety.protocol.en.md) owns Facety design intent. A default below is an experiment assumption, not a decision that closes a protocol OPEN item.

**D33 design boundary, 2026-10-23:** [protocol §46](facety.protocol.en.md#46-brightid-inspired-topology-design) selects Network Difficulty, effective-independent invitation support and dynamic consuls as design requirements, with operational contracts still OPEN. This documentation-only update does not implement them. Active-accepted counts, raw qualifying guarantor counts, fixed Council target 101 and the one-seat reference remain legacy research assumptions; no D33 one-consul authority, verified topology gate, quota, hysteresis or privacy proof is implemented. [BACKLOG](../BACKLOG.md#d33-topology-design-implementation-gated) owns migration. Existing snapshots/studies retain their original source and meanings.

**D34 liability/correction boundary, 2026-10-23:** [§20.6](facety.protocol.en.md#206-historical-event-liability-and-early-self-correction-d34) selects historical event-time guarantee responsibility and describes early self-correction. `preflightIdentityVerdict` still selects parties from the current graph and skips currently unaccepted parties; historical relation records and act/XP snapshots are not a complete D34 liability engine. Exit can therefore escape a modeled later fine under the legacy reference, even though D34 rejects exit as erasure of past responsibility. No self-dispute lifecycle or general spent-value restoration is implemented. Exact event/duty/time/collection and repeated-penalty contracts remain gated; source behavior and old studies are preserved, not reinterpreted as D34 compliance. The [D34 timeline preparation](../studies/2026-10-23-d34-timelines/README.md) shows that `guarantors` lists model-qualified recording-time guarantors and `xpRecipients` lists potential credit recipients; neither is an actual-credit receipt or complete legal-liability set, and current edges can differ, and a re-link can allow a pending right to credit the returning subject. It also demonstrates that equal numeric relationship/act timestamps do not preserve native event ordering. These are diagnostic observations, not new historical-role fields or an epoch policy.

## Architecture

```text
CLI / trial batches / sweeps / games / evidence -> experiment
experiment -> shared disputes / stake book -> model
experiment -> generators, metrics, observables, effort
causal examples -> evidence/sponsor reference + optional journal -> same disputes / model
CLI graph workbench -> graph algorithms
experiment environment -> noisy observations -> bounded veto response
model -> directed graph
generators -> directed graph, seeded randomness
metrics -> reachability
path algorithms -> graph public API
```

The model never receives a hidden label saying that a subject is an attacker or a real person. An experiment evaluator may maintain those labels outside protocol state. Detection and adjudication require separately described observations and policies; omniscient deletion of every attacker is not a defense.

## Implemented protocol subset

- Subjects keep rate limits, debt, XP history and graph identity across key changes.
- Time uses integer hours. A day is 24 hours; there is at most one rewarded Self-ID per rolling day. Simulation time never moves backwards.
- Artifacts have abstract detector outputs (`faceCount`), registration timestamps and selected face indices. The reference window includes age 24 hours. Different subjects claiming the same face flag every affected claim without submission-order guilt. Same-subject repeat use at that endpoint is an explicit research policy, not a second conversion of one act.
- A normal Self-ID mints one modeled FACY into Emitter custody. It cannot be transferred as an Emitter right.
- An own unspent right can burn for a target-bound invitation once it reaches `spendMaturityHours` (default 24). Conversion transfers, rather than mints, once it reaches `conversionMaturityHours` (default 24). No automatic conversion occurs.
- A new invitation is frozen for `invitationFreezeHours` (default 24); a current guarantor of the creator can cancel it during the freeze.
- An authorized guarantor can cancel an unspent right for as long as it stays unspent. Consumption and conversion permanently end that veto.
- Directed guarantees need a proposal from the guarantor and confirmation by the guaranteed subject. They do not create reciprocal guarantees or invitation lineage.
- Disconnection, invalidated identity and monetary liability are separate. `invalidateIdentity` marks only the adjudicated subject; it does not declare descendants false.
- Penalties are explicit exogenous inputs, not a claim that the simulator has solved adjudication.

## Research policies

`policyFrom(overrides)` rejects unknown keys and invalid values. Policies are immutable for the duration of a model instance.

- `xpFinality: "terminal"` (default) awards XP only when an act is consumed or converted. Cancellation awards no XP. `"immediate"` awards at acceptance, exposing the provisional-authority scenario for comparison.
- `cancellationAuthority: "snapshot"` (default) uses the act's eligible-guarantor snapshot. An ended relation can still authorize cancellation of its historical unspent acts. `"current"` instead checks the current active edge, including newly established edges.
- `guarantorEligibility: "active"` (default) requires an accepted subject with a non-cancelled Self-ID inside the preceding 28 days. `"accepted"` removes the activity requirement. Frozen acts still count for activity. At the exact 28-day boundary an act expires.
- `guaranteeFee: 0` (default) models an unfunded two-sided guarantee. A configured positive integer fee is paid by the guarantor from liquid FACY on confirmation and held in a fee vault, not burned. This is not the still-unspecified Emitter guarantee commitment.
- `councilSize: 101` (default) ranks eligible subjects by effective XP, breaking ties by JavaScript string order. Zero-XP eligible subjects qualify; fewer eligible subjects produce a smaller Council. A snapshot is an observation, not an implemented Council case.
- `councilEligibility: "active"` (default) makes the Council the XP leaderboard among currently active accepted subjects: those with an uncancelled Self-ID inside the preceding 28 days. Members drop out when their activity window expires. This follows the protocol owner's decision of 2026-10-22, recorded in §27.1; D33's later verified-count, topology and Council-phase requirements are not implemented. Recalculation does not imply actual turnover. `"accepted"` keeps every accepted subject eligible and was the implicit behavior before that date, including for the 2026-10-22 coalition study.
- `debtRecovery: "reserve-until-mature"` (default) marks a debtor's new Self-ID right as reserved while outstanding debt exceeds the debtor's already reserved rights. The reserved right stays in Emitter custody, where guarantors can still cancel it, and the owner cannot spend or convert it. When it reaches `spendMaturityHours` without a dispute lock, the next clock advance (or unlock) burns it, reduces debt by one and applies terminal XP. A cancelled reservation repays nothing. `"immediate-burn"` burns at acceptance and credits XP at once. It is retained only as a comparison policy, because it removes the selected free guarantor veto for debtors and makes their XP final sooner than everyone else's.
- `artifactReuse: "registration-only"` (default, legacy reference) rejects duplicate supplied content-hash registration but permits same-subject reuse of an existing artifact when both inclusive age/rate boundaries allow it. `"once-per-subject"` is the stronger no-reuse reference: reject a subject's second act on an artifact regardless of face, key rotation or prior cancellation/voiding. Other subjects may still use the shared artifact through age 24, including collision claims. Rejection occurs before minting, XP, claim flags, rate timestamps, ID allocation or events. This comparison exposes the §14.4 ambiguity without silently selecting a new production rule; neither variant detects unprovided hashes or perceptual duplicates.

Other explicit assumptions:

- Genesis subjects are independently supplied trusted roots with zero money and XP. No attempt is made to prove bootstrap trust.
- For `N28 = 0`, the research invitation threshold is one; otherwise it is the decimal digit count. The numeric clamp agrees with D33, but `N28` remains a legacy active-accepted count and does not implement verification, effective independence or a complete genesis contract.
- An invitation binds one target ID, has no expiration and is accepted once. The threshold applies to its creator, not its recipient. An invitation alone does not create a guarantee.
- A link break costs exactly one liquid FACY, paid by the party ending the link, and transfers it to fee custody. No hardship exception is assumed.
- A dispute lock prohibits both owner disposition and guarantor cancellation. Unlocking does not reset age. Opening a lock does not itself prove admissibility.
- XP halving rounds down. Credits and halvings are chronological. Cancelling an immediate credit replays current XP without that source; historical votes or decisions are not rolled back. The foundation intentionally has no final court decisions.
- A monetary fine burns collectible liquid FACY first and assigns the remainder to subject debt. Existing Emitter balances and reserved dispute stakes are not seized. Future Self-ID repays one unit of debt per mature uncancelled right under the selected `debtRecovery` policy; its valid identity work can still earn XP. Nominal debt is never counted as an actual burn. Tying the reservation to the spend window follows the selected veto rule; the seizure order itself remains OPEN.
- Monetary amounts use safe-integer FACY units, not production token precision. `penalize` rejects a fine that would make accumulated individual or aggregate debt unrepresentable before changing money, XP history or events. This is a numeric representation limit, not a calibrated economic ceiling. Signatures, key possession, media capture/detection, publication rights and lawful identity judgments are abstract inputs, not validated here.

### Native artifact registration and ID provenance

`registerArtifact` allocates an automatic ID only after publisher, face count, explicit ID and content-hash validation succeed. Rejected registrations reserve neither an ID nor a hash; identical later funded transitions retain their IDs and ordered events. Explicit IDs do not advance the generator, and automatic allocation skips names already occupied by explicit registrations. This deliberately changes generated-name collisions from rejection/retry to successful fresh allocation; explicit duplicate IDs still reject. The [native-ID diagnostic](../studies/2026-10-23-native-id/README.md) records the old drift and new controls.

This is model-validation atomicity, not rollback of a successful earlier action in a caller's multi-call helper. A successful artifact registration followed by a failed Self-ID remains a successful registration. Separately charged scheduler attempts/work are not refunded by this guard. Counter exhaustion, allocation failure and arbitrary callback/out-of-band mutation recovery are outside this bounded proof; no economic rule or D33 migration is selected.

## Invitation freeze and link-break XP

- `spendMaturityHours` and `conversionMaturityHours` (both 24 by default, protocol §17.3) set when an unspent right can be spent on an invitation or converted. The superseded 3/7-day schedule is `72`/`168`; the bounded incentive fixtures pin it (`LEGACY_FIXTURE_TIMING`) because their documented measurements were taken under it.
- `invitationFreezeHours` (default 24, protocol §18.5) keeps a new invitation open but unacceptable for that many hours. During the freeze, any current guarantor of the creator may `cancelInvitation`. The emission burned to create it stays burned, and the XP its consumption credited is revoked.
- `linkBreakXp: "revoke"` (default, protocol §19.3 DIRECTION): ending a guarantee removes every XP credit the guarantor earned from the guaranteed subject's acts, and snapshot rights credited later no longer reach a departed guarantor. `"keep"` is the comparison policy.
- `registerArtifact(publisher, { contentHash })` rejects reuse of a supplied registered content hash (protocol §14.4); the same-subject registered-artifact policy above is separate. `transferFacy(from, to, amount, memo)` records a public memo, so that flow analysis can separate ordinary transfers from dispute settlements and challenge rewards.

## Dispute stake custody reference

`disputes.stakeBacking` is **OPEN-policy research**, not a selected protocol default:

- `"unsecured"` (default) preserves legacy entry checks against current liquid funds without collateral deduction. Concurrent positions can reuse one balance; later spending, identity invalidation or fines can leave commitments unpaid. Ladder settlement collects up to remaining eligible liquid funds and creates no debt for the unpaid stake.
- `"reserved"` transfers each admitted position's full stake from the participant's liquid balance into `ledger.stakeVault` through `FacetyModel.reserveDisputeStake(caseId, owner, amount)`. Reusing or spending those funds is impossible through the model. `settleDisputeStake` releases a winner's own collateral, transfers a losing lower position to the winner above, or burns a losing top position (still an OPEN-case reference). A mooted case refunds all collateral; open cases at the horizon retain it as pending custody, not a loss.
- The reserved reference protects collateral from unrelated fines; those fines collect only unreserved liquid funds and otherwise create debt. Release is not automatic debt repayment. Settlement may passively credit a known invalidated account's refund/winnings, but does not restore identity, XP or spending rights. These priority/recipient choices are declared assumptions, not selected seizure or exclusion law.

The custody invariant is `supply = emitterVault + collector + feeVault + stakeVault`; `stakeVault` also equals the sum of still-reserved commitments. Zero-amount commitments are permitted for zero-stake experiments and still have one lifecycle. Invalid/duplicate reservations and invalid/duplicate dispositions reject before balance, custody, record or event mutation.

`DisputeStakes` owns the off-protocol case/position lifecycle, not XP or truth. It derives alternating sides, validates safe aggregate commitments, and delegates every monetary mutation to the model. A case settles or moots once; a replay rejects before collection, XP penalties or reputation-record updates in the experiment. These guards close the demonstrated private-helper replay hazard, not a previously proven scheduler exploit. Existing scalar stake/XP policy choices and case merits are not selected by this extraction. The book/scheduler exclusively owns its commitments; whole-case settlement is sequential, not a transaction/recovery manager for out-of-band settlement calls that desynchronize model and book. No reviewed scheduler path makes those calls. This ownership limit is distinct from atomic rejection of an individual model reservation/disposition or duplicate closed-case processing.

Every run retains `disputes.cases` (target, challenger, procedure, positions, clocks, status, procedural resolution reason and actual accounting) and `disputes.stakes`; histories retain cumulative stake summaries. `nominalLosing = transferred + burned + unpaid`. `released` is actual returned collateral, not profit. New group/system `stakeFacy` and `falseStakeFacy` facts keep pending custody visible and include it in evaluator false-circulating holdings. Valuing those facts requires explicit utility weights; an old artifact missing a selected-valued field remains unknown, not zero. The case reason names the actual reference termination trigger—environment verdict, response-window expiry, round/scan limit, incomplete entry, no willing entrant in the scan, Council intervention or moot target—not a human reasoned merits judgment. `maxRounds`/`maxScan` are legacy experimental termination references, not computational censoring or selected finality. A round cap can close a timed case immediately; it is explicitly reported as such, not described as waiting seven unopposed days.

The [diagnostic stake comparison](../studies/2026-10-23-accountability-audit/README.md) retains the original unsecured witness, a two-case custody comparison, and six exact differential checks against the old scheduler using the **current** model/support modules. That control is not a historical research replay or evidence beyond its contexts.

## Adjudicated chain voiding

`voidSelfIdChain(id, { fromAct })` is an explicit adjudication input, like `penalize`. It cuts a subject's Self-ID chain from one act onward (default: the whole chain): unspent rights burn with no XP, and XP credited by every cut act is revoked from all its recipients by chronological replay. Converted or invitation-burned coins cannot be un-minted, so recovering them requires a separate fine. No court procedure is implied.

**Repeated-call boundary ([diagnostic](../studies/2026-10-23-chain-replay/README.md)):** without new acts, repeated cuts do not repeat native burns or XP removal, but are not full-state no-ops: they emit another event, and converted/invitation-consumed acts receive another `+voided` disposition suffix. Returned `acts` counts selected non-cancelled historical acts, not necessarily newly voided acts; a later cut can include both already marked converted acts and newly appended rights.

`enforceIdentityVerdict`/`penalize` are explicit trusted adjudication inputs, not independently case-keyed replay guards. Reapplying the helper can fine/halve an accepted guarantor again after the target was invalidated. Relay closure and book settlement guards reject repeated processing of a finalized case; new challenges reject an unaccepted target, and timed scheduler resolution moots one. The new test covers upheld/rejected and repeated/reversed relay verdicts under both stake backings; traces may record refusal even when native/workflow state is unchanged. No scheduler replay exploit follows from calling the lower-level helper out of lifecycle. D34 selects historical event-time attribution, while separate verdict identity, overlapping cuts, precise historical duties and incremental fine bases still require the OPEN contract in §21.1; no deduplication policy is silently introduced.

## Counterfactual ablations

`ablations` (constructor option, `ablationsFrom`) removes a protocol mechanism for evidence experiments: `withholdGuarantorXp` limits Self-ID XP to its owner while keeping guarantor cancellation authority, and `fixedInvitationThreshold` replaces the N28 digit rule. Defaults are off. Any enabled ablation is a labeled counterfactual, not Facety behavior, and [evidence](evidence.en.md) owns how it supports necessity claims.

## Graphs and certificates

The model keeps invitation lineage and current guarantees in different `DirectedGraph` instances. Guarantee history is retained in relation records. Synthetic topology generators deliberately bypass admission economics: use them to test algorithms, not to claim economically feasible network growth.

Graph edge IDs are immutable and never reused after removal. `clone()` and JSON snapshots preserve identities and safe-integer counters. A restored counter at `Number.MAX_SAFE_INTEGER` can remain readable, but mutations requiring exhausted capacity throw `RangeError` before changing state. Removing a node preflights the revisions needed for every incident edge as well as the node itself. Node/edge deletion and rewiring return explicit mutation journals. Hub removal ranks initial total degree rather than recalculating adaptive centrality.

`graph.assertCapacity({ revisions: 1, edgeIds: 0 })` checks non-negative safe-integer headroom without changing counters or reserving slots. Revisions count the actual node/edge mutations; edge-ID slots count new edge allocations, not node additions or edge deletions. The default checks one revision and no new edge ID. This is a synchronous preflight, not a lock or transaction manager.

The model preflights complete numeric resource requirements before its first side effect. Confirmation checks one guarantee revision and one edge ID before collecting its fee; termination checks one revision before collecting the break fee. Admission checks two lineage revisions (node plus edge), one lineage edge ID and one guarantee-node revision before inserting subject state. Capacity rejection leaves subjects, graphs, balances, statuses and events unchanged in an otherwise coherent model. Tests inject near-exhaustion counters and cover rejection as well as exact remaining capacity.

This does not introduce whole-model restoration or make arbitrary external graph mutation a supported admission path. A monetary `audit()` alone does not certify graph/identity coherence; the atomicity tests compare the complete exposed protocol state. The preflight guarantee concerns numeric capacity, not arbitrary corruption, user-overridden methods or runtime allocation failures.

`findPathBfs` and `findPathBidirectional` search directed paths from a caller-supplied root set. Bidirectional search uses incoming edges from the target and expands whole layers. Both report `found`, `unreachable`, or `budget-exceeded`, with visited-node / edge-check counters. Bidirectional visited counts include both search trees.

`verifyPath` checks the certificate against the verifier's current graph, canonical root set, target and optional blocked nodes. It checks direction, simplicity and each exact edge identity. Removing and re-adding the same endpoints invalidates an old certificate. Unrelated changes preserve a path unless `requireRevision: true` requests snapshot-strict verification.

These are reachability certificates, not cryptographic commitments, proofs of media authenticity, global uniqueness or liability. The verifier must obtain its canonical graph and trusted roots independently. A graph exported by an attacker is not a trusted ledger.

### Path algorithm benchmark

`benchmarkGraphArtifact(artifact, { queries, roots?, iterations = 5, warmup = 1, measureTime = false })` in `graph-workbench.mjs` compares existing BFS and bidirectional BFS. CLI: `graph-benchmark <artifact.json> <options.json>`. [The executable example](../examples/graph-benchmark.mjs) creates a seeded preferential graph and retains reachable, self-root, unreachable, blocked and budget-exhausted queries. This is algorithm tooling, not a new protocol policy or a D36 disjoint-path implementation.

- **Inputs and replay:** `queries` is a non-empty array of `{ target, roots?, blockedNodes?, maxVisited? }`. Roots default to the artifact's roots, or the top-level override; each query can override them independently. Artifact exclusions remain in force alongside additional query exclusions. A bare graph snapshot requires independently supplied top-level roots. The result retains the full graph snapshot, its digest, generation/source metadata, effective queries, work counters and implementation/runtime provenance. The generator and randomness policy are unchanged. Unlimited output budgets are `null`; omit `maxVisited` in input for an unbounded search.
- **Correctness before timing:** every query first obtains an unbounded BFS reference, then both algorithms' preflight results. Found proofs must pass the independent canonical-edge verifier at the exact graph revision and match the reference shortest length. Unreachable results must match reference unreachability. All preflights finish before any warmup or timing. Every subsequent result is verified and must exactly match that algorithm's own preflight proof/status/counters; the graph snapshot must remain unchanged.
- **Measurement:** `iterations` is a positive safe integer; `warmup` is a non-negative safe integer. Algorithm order alternates by query and repetition. Timing is opt-in: `measureTime: true` retains raw local milliseconds and their sum, covering only the search call, including certificate construction. Graph generation/restoration, reference checks, independent verification, digesting and warmup are excluded. With timing off, all elapsed fields remain `null`, and identical seeded artifacts/queries give identical result content under the same source/runtime. Node/edge counters are algorithm work, not human effort; bidirectional visited counts include both search trees.
- **Truncation and scope:** `budget-exceeded` stays unknown and makes that case's `performanceComparable` false even if the other algorithm finishes. Independent verification checks found certificates, not a proof of non-reachability; the unbounded BFS reference supplies the reachability comparison. No aggregate speedup, stable machine-independent timing, optimal attack probability, personhood or independent human interests are inferred.
- **Bounds:** the harness rejects requests exceeding one million searches including references, preflights, warmup and samples. This bounds execution count, not graph size or wall time. Imported snapshots remain caller-supplied inputs; existing topology-generator edge limits still apply to generation. Existing-output refusal and explicit `--force` behavior are inherited from the CLI.

Benchmark smoke/differential tests cover all five synthetic topologies, round-tripped query/proof transport, shared snapshots, exclusions, independent root overrides, zero-edge proofs, local timing and preserved budget missingness. The exhaustive four-node algorithm comparison remains in `proofs.test.mjs`. No admission, Council, XP, economic or scheduler rule changes; the implementation fingerprint changes because the workbench source does.

## Bounded causal reference and inventory

The [mechanism chapter](research.en.md#executable-causal-core) owns the explanation; [mechanisms.json](mechanisms.json) owns stocks/flows, normalized experiment-control annotations, return/missing links and simplification records. Canonical examples `examples/causal-walkthroughs.mjs` and `examples/causal-relay.mjs` use `EvidenceRelay`/`CausalJournal` in `src/accountability.mjs`. The disconnected alternative relay/trace/walkthrough prototypes were [removed as dead code](../studies/2026-10-23-dead-code/README.md), not merged into these rules. The retained implementation has 25 source modules; older 28-module artifacts require their original source tree for provenance-exact replay, even though differential execution is unchanged.

This input-driven exclusive-owner reference has no automatic search or supreme court. Each observation, packaging, route, processed review and formal attempt costs one declared nontransferable work unit. Unavailable/conflicted/capacity-blocked reviews perform no review work; native setup/walkthrough effort is unmeasured (`null`), not free. Reviews have a separate per-day capacity. Current XP/liquid stake is rechecked through the scheduler's strict gate. External actors gain no subject/XP/rights, private access or compensation; no FACY is minted for their work. Source labels and signals establish neither correctness nor statistical independence.

Staged hearing times and supplied one-step verdicts are OPEN-procedure assumptions. Examples explicitly choose reserved backing, not a new default. Target invalidation moots/refunds pending reference custody. Monetary/XP/identity consequences use the native model and shared enforcement. Whole-verdict arithmetic preflight prevents aggregate-debt overflow before reference custody settlement; exact headroom including pending refund remains usable. This is normalized/coherent-state numeric validation, not arbitrary exception rollback, callback safety or out-of-band book recovery. Unexpected errors retain evidence when journal capacity permits and still throw; disabled/saturated journals count omissions instead.

Tracing bounds retention only; off/full/saturated and inert-read controls preserve semantic results. The example environment has a separate `causal-relay-input-keyed-v1` manifest; the full scheduler remains `decision-keyed-v1`. Example-source hashes accompany `provenance.implementation` because schedules/fixtures live outside `src`. Historical confirmation status does not transfer. See [raw/review/preservation evidence](../studies/2026-10-23-causal-core/README.md).

## Validation and optimization

Run `npm test`. Proof tests compare shortest-path lengths on every directed simple graph of four nodes, plus larger seeded topologies, blocked paths, adversarial certificates and mutations. Model tests establish custody conservation, reward limits, terminal rights, chronological XP and conditional policy behavior.

The graph uses indexed incoming/outgoing adjacency and constant-time edge counts. Searches use queue cursors, not array shifts. Topology generation and rolling activity/XP replay are deliberately simple reference implementations; benchmark before adding indexes or caches, and compare optimized implementations to the existing semantics.
