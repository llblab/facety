## Duplicate or opaque concepts and their consumers

1. **“Reputation” names three different signals—not duplicate parameters.**
   - Graph trust: screening and accused/challenger prior.
   - Win/loss record: opposing-entrant reliability and regular-noticer selection.
   - XP: formal rank/eligibility, plus declared private loss valuation.
   - Keep these separate in the causal register; merging would erase distinct inputs and falsifiers.

2. **`flowFlagged` is broader than flow tracing.**
   - `inspectionWork()` adds attention subjects to the same set and records its size before graph-screening additions (`src/experiment.mjs:974–987`).
   - Consumer: history/system trust metrics; games merge trust counters into retained `sanctions` (`src/games.mjs:88–92`).
   - **Risk:** interpreting this counter as exclusively money-flow detection, or as the full final screening pool.
   - **Next action:** document the exact historical measurement meaning; preserve compatibility.

3. **`eligibleForUnmodeledXpChallenge` is a historical name.**
   - Incremented whenever a suspicious no-veto-authority observation passes the XP comparison—even when an enabled dispute immediately handles it (`src/experiment.mjs:1049–1058`).
   - It is an opportunity counter, not necessarily an unresolved backlog.
   - **Next action:** annotate consumers before any rename.

4. **`rewardsReceived` includes all recorded incoming FACY transfers.**
   - Aggregation does not filter transfer memo (`src/experiment.mjs:1231–1233`), although transfers distinguish ordinary cash-out/payment from challenge reward and ladder settlement.
   - **Risk:** a game valuation may value “rewards” while actually valuing broader gross inflow.
   - **Next action:** retain current field semantics and distinguish transfer categories in explanatory evidence.

5. **Repeated accounting is not automatically redundant state.**
   - Incremental false-conversion count is checked against an independently recomputed count (`src/experiment.mjs:492–494`).
   - Model ledger totals are checked against outstanding rights and reserved custody (`src/model.mjs:490–505`).
   - Cohort effort is checked against action and phase totals (`src/effort.mjs:114–123`).
   - These are useful consistency checks, not deletion candidates.

6. **Historical timing is intentionally pinned.**
   - `LEGACY_FIXTURE_TIMING` and the fixed incentive schedule preserve an older 3/7-day comparison (`src/incentives.mjs:8–10`).
   - They are not duplicate current defaults or evidence that the current scheduler uses those windows.

## Specific falsifiers, evidence gaps and next action

| Claim to challenge | Specific falsifier / missing evidence | Recommended next action |
|---|---|---|
| Contribution rewards improve responsibility | More terminal XP with unchanged or worse selection/monitoring quality | Register reward accounting separately from the untested behavioral return. |
| Withdrawal disciplines influence | Lost historical XP deters exit more than it improves selection, or relinking restores unintended authority/credit | Preserve both-party, pending-act and relinking witnesses; do not infer incentive alignment from revocation alone. |
| Attention/gossip improve correction | Matched inspection effort finds more genuine-target harm, displaced detection or persistent false watch lists | Compare target allocation and downstream correct/wrongful outcomes, not attention counts alone. |
| Reputation improves accuracy | Early procedural errors generate reinforcing records that worsen later decisions | Use matched record-weight/notice controls and retain evaluator-correctness measurements separately from procedural wins. |
| Growth expands defense capacity | New subject workload exhausts shared budgets faster than useful defense grows | Separate subject count, operator count, performed work, denials and censoring. |
| Current tests establish all optional links | Cluster follow-up never actually fires; reputation/gossip settings change no downstream outcome in decisive witnesses | Mark those links source-implemented but effect validation incomplete; require positive-execution witnesses before stronger claims. |
| Measured return establishes recovery | Metrics return while wrongful invalidations persist, or return only to a compromised baseline | Keep `describeReturn` as a finite metric criterion; require separate restoration and irreversible-harm criteria. |
| Outsider discovery can reach judgment | Strong evidence cannot find an eligible, independent and funded sponsor—especially near the XP apex | Follow the existing bounded evidence→sponsor→dispute backlog slice; do not add a second court. |

**Handoff:** preserve the existing mechanics and defaults. The highest-value reduction is conceptual: label **protocol transitions**, **optional behavioral/procedural references**, **external assumptions**, and **offline measurements** separately. Most overclaim risk comes from silently connecting those layers, not from an absence of all feedback.
