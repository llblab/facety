# P16: bounded service-order discriminator

## Classification and execution boundary

**Unregistered exploratory design; controls implemented, experimental data not yet collected.** This is a D39/R1–R6 follow-up to F26's unresolved target-priority alternative, not a confirmation or a new Facety rule. The [design brief](../../docs/research-interactions.en.md#bounded-discriminator-service-order-sensitivity-p16) owns the causal question; [BACKLOG.md](../../BACKLOG.md#integrated-research-programme-d39) owns execution.

Only package service priority changes. Discovery/package creation and settlement stay in Mira/Aster order. Both valid permutations retain the same funded prefix, latent subject/stage draws, sponsor wallet/individual XP, two opportunities, 10 work units and 72–96-hour window. The relay stays a one-step reserved-stake reference, not the full cohort/Council pipeline or D33/D34 implementation.

## Frozen exploratory inputs

- **Sampling/bound:** 24 fixed fresh labels `d39-order-explore-00`–`23`, three existing contexts, three routing arms and two service orders: 432 runs. Contexts are independent/capacity two, independent/capacity one and shared-error 0.75/capacity one; this is not a full capacity × correlation factorial.
- **Controls:** Default arm outputs match baseline `94fec29` in 72 complete comparisons. An 18-run-per-version comparison wrapper matches except its intentionally changed example source hash. These use control labels, not stored scientific study inputs. Permutation, fixed discovery/settlement, one-package, matched member/relay, blocked routing and inert/saturated trace checks pass. Eight focused tests are included in 239 passing native tests; see `controls.json` and `validation.json`.
- **Measurements:** Retain raw evaluator inputs separately from protocol state, all metrics, refusal/precondition traces, actual collection/debt and pending stage clocks. Genuine burden is not automatically wrongful, and retained accepted identities are not voluntary participation. `traceLimit: 64` must retain all refusal evidence.
- **Inference:** Paired reverse-minus-canonical differences per arm/context, raw totals and 2,000-resample descriptive percentile intervals. No p-values, regime assignment, equivalence claim, confirmation, seed replacement or real-world attack/retention estimate. Shared seed worlds across arms/contexts are not extra independent people.
- **Untested:** Human preferences/effort, alternative prevalence/qualities, target populations, correlated capacity two, live arrivals/long horizons, sponsor pay, useful demand and selected historical-liability/topology migrations.

## Reproduction and outputs

Use Node.js 22+ and a checkout of the source/design checkpoint made **before** data execution. From the repository root:

```bash
node studies/2026-10-24-service-order/controls.mjs
npm test
node studies/2026-10-24-service-order/run.mjs
```

The runner fixes its inputs (no seed/size CLI override), validates every declared pair and writes `manifest.json`, `runs.json.gz` and `analysis.json` only after successful controls. It refuses existing outputs; use a fresh checkout of the pre-data source revision for reproduction, never overwrite retained artifacts. The manifest binds native implementation/randomness and hashes the example, funded world, runner, controls and relay tests. The source checkpoint revision and experimental results will be recorded after execution, without calling the exploratory design preregistered confirmation.
