## Observations and limits

Source/design was committed and pushed as **`3d895567f473dbdda436c10c666d722866f5c023` before the first experimental invocation**. The original source checkpoint contains no experimental data. Native implementation stays `0313a30912eb2a1caffeec361e769debc47750cceece0946c49d367d0ed84d9a` (27 modules); the manifest additionally binds the changed example/study sources and unchanged keyed-input policy.

There are **24 underlying seed-world labels**, reused across three contexts, three arms and two orders, not 432 independent observations. Each context has 11 underlying violations in those worlds. For both the member and external-relay arms:

- **Independent review, capacity two:** 7/11 violations corrected in either service order. All 14 retained outcome metrics have zero per-world differences; discovery, service/trace metadata and stage clocks are not asserted identical.
- **Independent review, capacity one:** also 7/11 in either order and zero per-world differences in those metrics. These finite nulls are not equivalence, safety or population-capacity proof.
- **Shared review, capacity one:** Mira-first corrects 9/11 versus 8/11 for Aster-first. Exactly one of the 24 paired worlds changes correction, none in the opposite direction. Reverse-minus-canonical correction is −1/24 per world; the descriptive 95% bootstrap interval is **[−0.125, 0]**. No multiplicity-controlled inference is made.

The unrouted arm opens no cases (0/11 corrections), an encoded missing route rather than emergent social behavior. Member and relay protocol outcomes remain identical within each order/context: this is a matched-resource placebo, not extra independent evidence or a workforce advantage. No wrongful invalidation occurs in these 24 worlds, which does not establish absence of risk.

**Inspected trace witness:** `d39-order-explore-03`, shared-review/capacity-one. Both packages are suspicious; the Aster allegation is false and its supplied verdict would reject it. With Mira first, the valid Mira case opens and Aster review is capacity-blocked. Reversing service consumes that sole review on Aster; Mira becomes capacity-blocked and remains uncorrected. Both variants use 8 work units, pass the same 7>3 XP/1-FACY stake access check, and have no work-budget denial. Discovery/verdict inputs are identical; settlement order is fixed. This is a diagnostic execution of an encoded finite-service rule, **not a discovered emergent mechanism**.

Recorded burdens also differ. In that witness, genuine-subject XP loss is 8→4 and collected penalties 3→0 FACY as correction disappears; the rejected allegation's challenger still loses XP/stake. Across the shared-review relay arm, genuine XP loss is 88→84 and collected penalties 27→24. Those burdens are not automatically wrongful, and less burden with more missed fraud is not an unqualified welfare gain. Debt, actual collection, burned value and pending packages remain separate in the raw data.

**What this narrows:** service allocation can change this reference's outcome even at identical evidence/work; it cannot be assumed irrelevant. It neither establishes a general capacity/correlation effect nor resolves why real guarantors leave. Do not infer that copied review is preferable, that Mira-first is an implementable truth-aware policy, or that the old F26 study has been reclassified. Two independent source/data lenses and a bounded verifier subsequently found no supported result-affecting defect; the [retained review](review.md) preserves the unresolved preflight and downstream source-fidelity qualifications rather than claiming complete pipeline acceptance. No extra seeds were added to obtain this witness.

- **Sampling/bound:** 24 fixed fresh labels `d39-order-explore-00`–`23`, three existing contexts, three routing arms and two service orders: 432 runs. Contexts are independent/capacity two, independent/capacity one and shared-error 0.75/capacity one; this is not a full capacity × correlation factorial.
- **Controls:** Default arm outputs match baseline `94fec29` in 72 complete comparisons. An 18-run-per-version comparison wrapper matches except its intentionally changed example source hash. Eight focused tests are included in 239 passing native tests; see `controls.json` and `validation.json`.
- **Measurements:** Retain raw evaluator inputs separately from protocol state, all metrics, refusal/precondition traces, actual collection/debt and pending stage clocks. Genuine burden is not automatically wrongful, and retained accepted identities are not voluntary participation. `traceLimit: 64` must retain all refusal evidence.
- **Inference:** Paired reverse-minus-canonical differences per arm/context, raw totals and 2,000-resample descriptive percentile intervals. No p-values, regime assignment, equivalence claim, confirmation, seed replacement or real-world attack/retention estimate. Shared seed worlds across arms/contexts are not extra independent people.
- **Untested:** Human preferences/effort, alternative prevalence/qualities, target populations, correlated capacity two, live arrivals/long horizons, sponsor pay, useful demand and selected historical-liability/topology migrations.

## Reproduction and outputs

Use Node.js 22+ and a checkout of the source/design checkpoint made **before** data execution. From the repository root:

```bash
node studies/2026-10-24-service-order/controls.mjs
npm test
node studies/2026-10-24-service-order/run.mjs
```

The runner fixes its inputs (no seed/size CLI override), validates every declared pair and writes `manifest.json`, `runs.json.gz` and `analysis.json` only after successful controls. It refuses existing outputs; use a fresh checkout of the pre-data source revision for reproduction, never overwrite retained artifacts. The manifest binds native implementation/randomness and hashes the example, funded world, runner, controls and relay tests. The pre-data source revision above and `validation.json` identify execution/compatibility and artifact hashes. `manifest.json` records inputs/source identity, `runs.json.gz` retains all raw paired states/traces and `analysis.json` retains every per-seed difference, refusal count and descriptive interval. This is not retrospectively registered confirmation.
