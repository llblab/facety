## Refresh and budget semantics

The updater traverses current target roots in canonical order. Unaffected complete parent/distance rows are cloned into new private maps; this is semantic reuse, not zero allocation or structural sharing. Affected roots run the same sorted-neighbor/depth/score BFS as full rebuild. Reused rows consume total retained-node capacity; fresh admitted nodes/trials count separately. FreshTreeNodes means BFS admissions, not every allocated/exported row. A partial fresh root stays parent-closed; once construction is blocked, later roots are explicitly omitted. A reused tree is either retained whole or omitted, never truncated by UTF-8 row order. Exact-last bounds are not censoring until another operation is needed.

The new forest reference affected-root-bounded-bfs/v1 and originRoot identify current-equivalent tree semantics, not all rows freshly constructed at that capture. Standard stats describe current preparation/fresh BFS and total retained nodes; the serializable report separates old/current preparation, projected changes, eligibility/classification, reused/rebuilt roots, reused/fresh/retained nodes and fresh trials. Root retirement is index-only; removed anchors can still transit. Difficulty changes alone need not rebuild per-root topology, but proposals/verifiers still consume the new difficulty. Empty complete root sets assert no D support.

Preparing full captures already costs outside this method; deriving projections/delta, sorting, cloning/exporting, classification and allocation are additional update work beyond freshExpansions. No O(k*r) total-work, physical-memory, arbitrary-churn complexity or speed claim is made. This is whole affected-root refresh, not within-root insertion relaxation or Even–Shiloach decremental repair.
