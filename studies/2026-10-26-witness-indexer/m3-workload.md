## Choice and scope

Choose a small fresh-state synchronous batch runner over explicit supplied frames and ordered operations. An external hand-calculated trace is cheaper but cannot enforce repeatable cross-query load/state accounting; a persistent all-cache/indexer/service coordinator is premature and couples routing load to TTL/use/fallback. This first composition covers existing build/E1 refresh/E2 repair plus C3 prefix/tree queries and one named load window. Whole-witness/segment caches, learning, automatic maintenance/fallback, bidirectional/unit-split assembly, Native economic execution, graph generation/capture, wall time/heap profiling, CLI/daemon/network and scientific experiments stay outside it. Do not silently implement a universal indexer or replace old APIs.

Add `src/path-witness-workload.mjs`, owning only bounded supplied-frame tree-maintenance/prefix-query traces and peer-selection accounting; exclude canonical facts, pool ranking, proof acceptance, cache lifecycle and admission. Public surface is `runPathWitnessWorkload(input)` and frozen `PATH_WORKLOAD_LIMITS` with exactly maxFrames16/maxSteps128/maxPoolsPerFrame64/maxLoadIds4096. These are software input bounds, not human rates, quotas, calibrated scale or total CPU/RSS guarantees. Dependencies go down to public view branding, tree build/refresh/repair/prefix APIs/limits, pool routing/limits, context normalization and provenance/standard crypto; no Model/graph mutation, private source reach-through, ambient RNG, external callback port or entrypoint import.

## Exact input and complete preflight

Input is exact `{domain,frames,steps}`. Frames are dense bounded rows `{id,view,pools}`; pools are dense bounded `{subject,pool}` rows. Frame IDs and pool subjects are unique within their scopes; every view/pool is locally constructed and immutable/branded. IDs are nonempty well-formed Unicode<=256 UTF8 bytes; domain and query subject must also fit each applicable frame's existing witness context. Pool-subject IDs use the existing prefix-advice envelope, not invented personhood eligibility. All frames must share capture reference and storage graph name; labels/brands/hashes do not authenticate ledger lineage. Policy/epoch/standing/anchors may differ as supplied. Every step references one declared frame. The raw union of retained pool peer IDs across all frames must fit4096, including unused/duplicate-subject-across-frame entries before execution; this bounds the possible load-key universe, not accepted people. Empty frames/steps/pools are allowed subject to step references. Copy normalized frame pool rows in unsigned-UTF8 subject order and use that same order for advice and frame bindings; preserve declared frame/operation order.

Operation rows are exact: build `{op,frame,query}`, refresh/repair `{op,frame,query}`, query `{op,id,frame,subject,query,routing}`. Query-operation IDs are unique across the batch and become the unchanged C3 caller queryId; never use array position as a random key. Routing is exact `{seed,step,mode}` with existing seed byte/integer/uniform-or-best-of-two rules. Every nested method query requires its existing complete explicit field set and software caps, including zero; no defaults, budget translation or extra knobs. C3 maxPrefixHops<=that frame's policy.maxHops. Context is derived as `{domain,subject,policy:frame.view policy}`. Users supply pools but never load snapshots in this profile.

Validate all raw bounds, dense/exact/data fields, IDs, brands, namespace, referenced frames, policies, method configs and routing before the first SUT operation or owned load/state update. Accessors/sparse/non-natural/negative-zero/overflow/foreign/copy/unsupported values throw, not a workload miss. Zero-count pool-route checks may establish brands without drawing randomness; their normalization/scan cost belongs to preflight, not free query work. No future frame may prepopulate positive or zero load rows in earlier records.

Preflight may track a symbolic active frame/epoch using only snapshot/epoch metadata to reject a known cross-step active-forest policy mismatch before work. Build availability follows the existing builder (snapshot existence; do not add a grace check it lacks). Refresh/repair availability follows existing grace/snapshot rules; a missing active forest stays missing. Query requires matching active/frame policy when active exists, even if a later availability guard would fail. This is input-flow validation, not epoch adoption, tree construction or lookahead into query/search outcomes. Actual source availability/state disagreement throws. Preflight totals may change when valid future frames are appended; earlier per-operation observations/keys must not.

## Owned active forest and explicit maintenance

Each invocation starts with no active forest/origin capture and an empty load map. Build calls the old builder once. Refresh/repair call their named existing method once with the active forest, its tracked construction/current-equivalence frame view as origin, the requested current frame view and explicit budget. This ephemeral owner tracks a supplied origin; no old tree constructor starts retaining captures or exposes a generic persistent state handle. No method is automatically selected or retried on a query, miss, partial tree or update.

A non-unavailable returned forest replaces active state and records the requested current frame as its origin, including censored forests containing only partial/settled subsets according to that method's own contract. A called unavailable maintenance result clears active state; never secretly keep the previous forest. Build's unavailable local forest is recorded as its source outcome but not retained active. Refresh/repair without active state do not call the SUT: emit unavailable/forest-missing with called:false and work:null. A later explicit build can recover. Retired roots/transit/debt/authority semantics remain the original methods', never inferred from batch labels. Query never changes active state.

A query without active state similarly emits unavailable/forest-missing/feasible:null, called:false, work:null and empty loadDelta. Otherwise call `proposePathWitnessFromPrefixes` once using the active forest, that step's current view/context, explicit C3 query and derived advice for that frame. Stale origin versus current view is permitted advice; existing full current checks and both verifiers remain authoritative. Preserve actual found/miss/censored/unavailable/reason/feasible/required/coverage, including partial positives and unknown nonpositives. No oracle/cache/funded admission/Model mutation is hidden behind a query. Source exceptions or schema/counter disagreements throw the batch; they are not converted to safe no-path/status rows. An errored batch returns no accepted report, not evidence that no work occurred or a denominator-safe omitted trial.

## Actual load unit and snapshot timing

Load policy is `run-cumulative-route-selections/v1`: L(v) is the number of occurrences of v in completed called queries' **actual prefix.routes[].selected** arrays earlier in this invocation. Start empty/default0. Repeated peer appearances from alternate prefixes count repeatedly, not once per query or distinct vertex. This is a count of software routing selections/offers, not enqueued prefixes, expanded branches, consumed joins, accepted witnesses, CPU, served remote requests, outstanding concurrent work, human effort, XP, verified usefulness or economic capacity. Never name it generic measured network load.

Immediately before a called query, construct complete per-retained-pool load rows from that one L snapshot for best-of-two; uniform gets loads:null but still accrues selection counts. Every prefix route in one C3 call sees the same pre-query snapshot; no intra-query online reservation or feedback. Returned pool arrays remain unchanged. After the complete source call and counter/positive-verification agreement checks, fold all actual selected occurrences, including offers from prefixes never enqueued/expanded due to budget and queries returning miss/censored/partial-positive. Unavailable source queries have no emitted routes and add zero. This is not refund-by-success. Atomically add the fold to owned L only after the call returns valid; errors do not produce an accepted accounting report. No synthetic charge for raw candidates, samples that lose best-of-two, scan trials or tree admissions.

L is cumulative across frame/policy/epoch changes under the declared same-namespace assumption, not an automatically resetting window. No clock, decay, subtraction, externally supplied initial stock or TTL is introduced. Future new peer IDs default0 until actually selected. Safe-integer per-peer/total additions are checked. Bounded source caps and128 operations imply small enough logical counts; do not silently saturate/wrap or turn missing into0. Only known absent prior selections default0. All-zero concentration is null, never equality/safety evidence.

## Frozen report and resource meaning

Return deeply frozen serializable `{schema,reference,provenance,domain,namespace,frames,preflight,rows,totals,finalForest}` with schema `facety-path-workload/v1`, reference `bounded-prefix-route-load/v1`, current implementation/runtime provenance and namespace `{reference,storageName}` (null when no frames). Frame bindings are ordered `{id,viewRoot,policyId,currentEpoch,pools}` with sorted `{subject,poolId}` rows; they bind each requested current capture as well as the active-origin descriptors. Exact caller views/pools/steps remain necessary for reproduction: roots/pool IDs are neither reconstructible data nor authentication. Preflight records frames/steps/poolRows/retainedPoolEntries/distinctLoadIds/poolChecks; these count supplied validation inventory, not physical capture/hash/CPU work. Rows are ordered exact `{index,request,called,activeBefore,activeAfter,result,work,loadDelta}`. Request is the normalized explicit operation. Forest descriptors are null or `{viewRoot,policyId,epoch,reference,status,reason,complete,eligibleRoots,retainedRoots,treeNodes}`; counts describe index inventory, not independence or people.

Maintenance result is `{status,reason,reset,deltaComplete,retiredRoots,rootActions}`. Build has null reset/delta/retired/action detail (its raw build counters remain work); refresh/repair retain their report's reset/delta and root-action counts/retired count, with null action/retired detail when unavailable rather than false no-change inference. Missing-active maintenance uses unavailable/forest-missing and null details. Work is null when uncalled; called build uses `{build:meta.stats}`, refresh/repair `{forest:meta.stats or null,maintenance:report.work}`. Do not sum duplicate forest/report counters or translate E1 freshExpansions into E2 predecessor trials.

Query result is `{status,reason,feasible,required,coverage,proposalDigest,wireDigest,wireBytes,verification}`. Coverage is the original prefix coverage/null. proposalDigest is SHA256 of exact UTF8 JSON.stringify(raw source proposal), method `sha256-json-path-proposal/v1`; null if uncalled. Positive wire digest is SHA256 of its exact UTF8 bytes/byte length, with both accepted flags; absent wire/digests/verification are null, not zero or a returned certificate. This is telemetry, **not a witness-delivery API**; raw proposals still pass their original full verification before reduction, and digests are not authentication. Query work is `{proposal:source.stats,prefix:source.prefix.stats,accounting:{loadRowsBuilt,routeRowsFolded,selectedPeersFolded,proposalBytesHashed}}`; unavailable called results retain source zero/null distinctions. loaded rows are the complete retained pool rows constructed for best-of-two,0 for uniform. Folded counts must equal actual routes and source routedPeers. No M1/ref2 total CPU metric is invented from accepted flags.

loadDelta is sorted unique `{id,before,selected,after}` for actual offered IDs only, empty on maintenance/uncalled/unavailable; no future-universe zeros. Totals are exact `{operations,queries,loads}`. Operations has build/refresh/repair/query entries each `{requested,called,skipped}`; queries has found/miss/censored/unavailable counts including forest-missing. Loads are `{unit,total,distinct,max,herfindahl,rows}` with sorted positive `{id,load}` rows, max0 and herfindahl:null when total0. Exact totals/squares use BigInt internally before finite ratio conversion; data counters remain safe integers. No untyped total-work scalar, weighted cost, admission ratio or probability is added. finalForest is the final descriptor/null, not a new live state port.

Keep only active forest/origin pointers, bounded owned load state and compact rows; do not retain full per-query prefix paths/routes/witness wires or old parent forests in the report. Processing/hashing a full source proposal still materializes source data and has CPU/allocation cost. Supplied immutable captures/pools, validation, original preparation/search/verification/copy/export, driver load-row/fold/hash work and output retention are distinct. Bounds do not cover all bytes/physical memory or wall time. No benchmark curve, resource-price/fee conversion, calibrated human model or workload dominance claim follows.

## Randomness and acceptance

Best-of-two may legitimately change when earlier selections change the declared L snapshot: do not mislabel causal state dependence as consumed-stream coupling or promise blanket unrelated-action invariance.
