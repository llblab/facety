[Contract evidence](https://github.com/llblab/facety/blob/8b77cd8319f8613269586d1ce665828410e9fd03/studies/2026-10-26-witness-indexer/m3-tree-refresh-contract-validation.json) checks existing rebuild/proposal/verifier behavior, not a new updater. Live ranking/epoch authority, capacity/funded/default migration and master research gates stay unchanged.

## Scope and owner

Add `refreshPathWitnessTrees(forest,origin,current,query)` to src/path-witness-trees.mjs. Query is the existing exact build `{epoch,maxExpansions,maxTreeNodes}` with unchanged PATH_TREE_LIMITS, nonnegative safe integers/no negative zero. Origin/current must be locally constructed immutable views; forest must be locally branded. Origin root and policy ID must match the supplied forest's construction/current-equivalence metadata. Origin/current capture reference and storage graph name must match. These are operator-declared lineage checks, not ledger authentication; unrelated same-named captures must not be mixed. Invalid/copy/schema/namespace/origin data throws before refresh work, including on an otherwise unavailable target.

A wrapper that merely rebuilds on every capture change would duplicate existing buildPathWitnessTrees and is not this deliverable. E1 instead preserves complete unaffected anchor trees and rebuilds affected trees, with explicit bounded partial/omitted roots. It is **whole affected-root BFS refresh**, not insertion relaxation or within-root Even–Shiloach repair, dynamic completeness under arbitrary churn, or a speed claim. Existing full rebuild remains the reference/control; local decremental/insertion optimization is later work, not silently marked delivered.

Keep old constructors/proposal APIs, limits, output streams and routing keys unchanged. No new generic indexer framework, mutable daemon/handle, callback port, RNG or public resource constant is needed. The same owner may factor private projection/BFS/forest construction seams while preserving old outputs. No origin capture is retained implicitly by the old builder: the caller explicitly supplies origin, and successful refresh returns a forest current-equivalent to current. The caller can then use current as the next origin. Old forests/views remain immutable and usable under their own supplied state.

## Availability and target facts

Normalize all inputs before availability returns. The caller chooses epoch explicitly; never adopt/advance it automatically. If target epoch is future/outside current policy grace, or its snapshot is missing, return forest:null and unavailable report, with no projection/diff/BFS work. This does not change the old builder's diagnostic ability to prepare other epochs; no built/reused forest grants epoch authority or atomic permission.

Current target roots are exactly the existing builder's snapshot anchors that are live and not removed, in unsigned UTF-8 order. Retire old roots absent from that set; retirement affects index membership only, not canonical removal/guilt/history. Newly present target roots need construction. Removed anchors can still be intermediary vertices under ordinary score/edge policy. Snapshot difficulty changes alone do not change an individual BFS tree or select adopted D; proposals and both verifiers still read current difficulty.

## Complete change classification, not notice trust

Prepare the old and current **projected forward BFS graphs** from their full supplied live graphs: stored y→x is forward from anchor-side y toward subject-side x; any-live adds both projected directions when either stored orientation is live; reciprocal requires both. Compute the symmetric difference of projected arcs and its set of source vertices. Stored edge-ID reincarnation, source chronology and metadata-only changes do not become projected edge changes. A disappeared reciprocal orientation can change both projected directions, while an any-live orientation loss may change neither. Do not classify only parent edges or consume untrusted notices as a complete delta.

When minStanding is enabled and policy is unchanged, compare each relevant live vertex's old/current qualifying Boolean (known score>=threshold); unknown/null is not zero/qualifying. Score changes within the same eligibility class do not affect BFS. When score gating is off, declared scores have no traversal effect. At each root the root itself is exempt from this score gate, never its other intermediaries.

Use reset-all rather than selective reuse when the input forest is incomplete/unavailable, selected epoch changes, or full policy ID changes. In reset-all mode skip old projection/diff/classification: report deltaComplete:false and zero old-preparation/classification work, not an assertion that no changes occurred. In the selective mode report deltaComplete:true after deriving the complete delta. For unchanged epoch/policy with a complete input forest, root A is affected iff it is a new root, or its old complete BFS contains a vertex V at distance<r such that V is a changed projected-arc source, or V!=A and its eligibility Boolean changed. Classify exactly this conservative set; conservative means possible BFS change, not permission to rebuild every root and bypass selective reuse. Scan old per-root node records and test changed-source/eligibility sets, bounded by retained old rows<=65536, rather than multiplying all roots by every changed edge. Root-set changes alone do not invalidate other roots' trees. Isolated non-root nodes may change capture content without affecting any tree.

Why insertions matter even with all old parents live: a new shorter/tie route can change BFS. For a new bounded path, the first changed arc/eligibility transition has an unchanged old prefix, so its source/changed vertex occurs in the old complete root tree within the extension bound. Deletions and batches of mixed changes are covered by that same affected-set rule. Distance r vertices need no extension; a newly shortened prefix is already caught at its first earlier change. Rebuild every marked root to preserve the existing deterministic sorted-neighbor BFS parent choice, not merely distances or an arbitrary valid parent. This is a proof obligation to falsify independently before relying on the classifier.

## Ordered bounded construction

Prepare current sorted projected adjacency once. Visit all current target roots in builder order. For a complete unaffected root, retain its exact old parent/distance tree if it fits the remaining **total retained** maxTreeNodes. Reused rows consume that capacity even if no BFS expansion is performed; copying/retaining/index/export costs are not free. Otherwise build the root from current facts with the existing exact depth/score/tie semantics. Root plus every newly admitted node consumes retained-node capacity; every attempted fresh neighbor trial consumes maxExpansions, including already-seen nodes.

If another root/reused tree cannot fit, stop construction and omit it and all remaining roots. If fresh BFS is blocked by another neighbor/node trial, retain its valid parent-closed partial tree, stop further roots and mark incomplete. Never truncate a reused tree by arbitrary UTF-8 row order, which could drop an ancestor. Exact-last capacity/trial exhaustion is not censoring unless another operation is needed. A zero-expansion update can retain complete unaffected trees; it is not evidence that fresh construction is free. In reset-all mode the parent rows/status/coverage must match existing bounded full rebuild with the same query, excluding the explicitly different maintenance metadata.

Forest anchors still enumerate the full current eligible target set even if some roots are partial/omitted, as with the old builder. Missing paths remain advice misses. No stale affected subtree is silently served as current-complete. Positive paths from partial results still undergo full current checks and both verifiers; no result of this updater certifies D support, global infeasibility, people or financial permission.

## Output and resource meaning

Return exact `{forest,report}`. Forest is a newly branded immutable current-equivalent forest, or null when unavailable. It keeps existing path/anchors/toJSON and query-consumable meta fields, using reference affected-root-bounded-bfs/v1; meta.originRoot names the capture whose tree semantics were checked, not a claim that every row was freshly computed. meta.status/complete are built/true only if every current root is complete; otherwise censored/false. Standard meta.stats preparation/trial fields describe current adjacency and fresh BFS work; treeNodes counts all retained nodes, including reuse. Keep actual reuse/fresh work separate in report. Old constructor outputs are not relabeled.

Report is deeply frozen serializable data: schema facety-tree-refresh/v1; originRoot/currentRoot; normalized query; status refreshed/unavailable; reason ok/tree-node-limit/build-expansion-limit/epoch-outside-grace/snapshot-unavailable; reset null/input-incomplete/epoch-changed/policy-changed in that priority; deltaComplete as above; retired old root IDs; and current-root actions `{anchor,action}` with action reused/rebuilt/partial/omitted. Before availability reset/deltaComplete are null and action/retirement arrays empty. changedArcs is the number of changes actually enumerated, so zero with deltaComplete:false/null must never be interpreted as an unchanged graph. No mutable view/graph/Model/cache/forest implementation is embedded in report.

Report work has nonnegative counts preparedOldNodes/preparedCurrentNodes/preparedOldEdges/preparedCurrentEdges/oldProjectedArcs/currentProjectedArcs/changedArcs/scoreEligibilityComparisons/classificationNodeChecks/reusedRoots/rebuiltRoots/retainedTreeNodes/reusedTreeNodes/freshTreeNodes/freshExpansions. Unavailable work is all zero. RebuiltRoots includes a started partial root; root actions and retained-parent closure must agree. Preparation scans, set diff/lookup, sorting, copying, serialization, allocation and CPU are not hidden inside expansion count. Prepared node/edge counters count the live capture rows actually walked, separately from projected arcs. Full source capture/storage preparation already occurred outside this updater and must not be relabeled as update work or hidden in later performance comparisons. Do not call these counters measured CPU, O(k*r) total work, O(A*m*r) arbitrary-churn update complexity, physical memory or calibrated human effort.

Refresh mutates neither supplied graph/forest/view/options nor Model, caches, pools/loads or TTL/use counters. It performs no cache invalidation, implicit fallback/global search, source replay, eligibility/ranking inference, case judgment or sanctions. Current canonical facts and final certificate checks remain supplied explicitly, never delegated to an advisory delta/index.

## Acceptance and remaining boundary

Pre-code existing-API controls should retain: live-parent insertion shortening, chosen-parent deletion with an alternate current path, any-live versus reciprocal orientation loss, removed-root retirement with permitted transit, enabled/off score effects, incomplete versus larger-budget rebuild, explicit epoch/missing/grace cases, and identical-capture rebuild equality. These explain dependencies, not new refresh behavior.

Implementation must compare complete refreshed parents/distances with a separately written raw projected-graph BFS and a sufficient-budget full rebuild; test the affected set on all bounded tiny old→new graph pairs, including mixed insert/delete batches and unchanged distances with changed tie parents. Compare reset/bounded outputs to direct rebuild before any performance work. Cover qualification toggles/root exemption/unknowns/score-off, live node/target/difficulty/policy/epoch changes, old incomplete resets, total retained-node versus fresh-expansion zero/exact/one-less limits, parent-closed partial trees and omitted reused roots, inert immutability/strict preflight, r64/D64/>64 roots/Unicode, Native read-only capture, proposals/full M2/both verifiers, all old digests and current cached-tail behavior. A changed construction reference must not weaken full witness roles or migrate cache edge IDs into M1.

This contract does not implement refresh, local Even–Shiloach/insertion relaxation, workload accounting, an authenticated update stream or the broader indexer acceptance target. No experiment/benchmark/confirmation, G1/E1–E8 result, reserved seed, live ranking/epoch activation/capacity/funded/default migration or D62 economic guarantee is delivered. The next bounded cohort is this updater and its independent controls; subsequent within-root repair and research costs remain explicit work in BACKLOG.
