## Owned forest, cache and explicit operation order

After preflight construct one new PathWitnessCache at zero stats, active:null. Execute declared steps once in order. Build always calls the named builder once. Refresh/repair call their existing method once only with active.forest, its tracked construction/current-equivalence frame.view as origin, target frame.view and exact budget; no active means called:false/unavailable/forest-missing/work:null. A non-unavailable built/returned forest (including censored partial/settled advice) becomes active with target frame as origin. A called unavailable maintenance clears active; never keep old state or adopt the queried current frame as a new construction origin without maintenance. A later explicit build recovers. Query/invalidation never update active/origin.

**The whole cache survives every maintenance outcome, policy/epoch/reset and active clearing.** No automatic invalidation/TTL sweep/clock advance occurs on frame change, snapshot/anchor change, construction or inert stats read. Old entries may occupy FIFO space until actual lookup/probe expiry, explicit notice or normal eviction; current full verification/policy/subject/epoch keys remain authoritative. This is engineering cache state, not preservation/erasure of historical financial liability.

Query with active calls queryPathWitness once on that forest and the requested current frame/context/input, allowing old-origin/epoch/unavailable advice according to G's contract, without implicit maintenance. Query without active is explicitly uncalled: result unavailable/forest-missing/feasible:null/source:uncalled, work:null, no probe/oracle, no lastTick/TTL mutation. Do not silently use G's more permissive unavailable-handle path or bypass the missing forest. Requested query ticks remain preflight monotone even when no call occurs; final cache lastTick is the last **actual** query admission, not last declared tick. A called query retains G's cache/union/oracle status/current proof and1/2 cache admissions; no load ledger or segment use is introduced.

Invalidate always calls the owned cache's native invalidate once, even without active state, and retains its actual evicted/edgeNotices/anchorNotices result. It does not read/change frame facts, active forest, clock or expiry. Spurious notices may evict a valid proof; absent notices never make invalid current proofs acceptable because G still full-verifies. Notice counts/evictions/reverse cleanup are advisory work, not an emergency judgment, node exclusion, relationship end, cache-clock event or statement of canonical completeness. Duplicate notices can report several inputs but evict one entry. No implicit propagation to segments/other indexers occurs.
