## Purpose, alternatives and gate

Choose native paired conformance tests around current public APIs and compact F1 receipts. Do not add another runtime comparator/API/experiment engine, private debug port, persistent service or performance command. Comparing whole receipt hashes is cheap but wrongly treats construction metadata as semantic drift; comparing only found counts misses stale/noncanonical tree rows and dropped unknowns. ## Fixed supplied fixtures and matched tapes

The plan fixes16 unit cells:12 complete-equivalent,4 bounded-diagnostic. Ten directed complete cases cover ID-only reincarnation/no projected change, shorter insertion, full-prefix tie propagation, deletion/unchanged boundary ingress, disconnected cycle, score gain/loss, root retirement with allowed transit, policy reset, supplied epoch reset and an intentional single-tree family miss. Two more explicitly supplied any-live/reciprocal orientation-loss cases do not select a default direction. Four bounded cells cover zero-node positive prefixes, exhausted update operations, whole-retained versus partial-node truncation, and the builder/maintenance grace-availability difference. IDs/edges/scores/roots/epochs/queries/budgets are exact in the plan, not calibrated people or plausible sampled networks.

For each cell, compile three separate fresh F1 calls in fixed arm order rebuild/refresh/repair. Each starts with the same explicit initial build and empty cumulative selection ledger. Each round uses the same requested frame/epoch, substituting build/refresh/repair with its own explicit budget. Queries remain byte-identical across arms: IDs/domain/subject/current frame/policy/epoch, pools/ranks, seed/step/mode and every C3 budget. Never salt random keys by arm, array position or implementation tag. F1 owns normalization, active clearing/recovery, lagged load and its original resource/availability semantics; no wrapper fallback, refill, extra query or reset of L is allowed.

Bounds for this unit fixture compiler are15 rounds and4 queries per round (at most76 F1 operations including initial build), within unchanged F1 frame/pool/load limits. The sealed plan uses one round and two queries per cell (uniform and best-of-two). Each initial build uses its own declared epoch; within a round all three maintenance epochs agree with that round's query epochs. Complete-equivalent cells also share the same retained-node cap. Equal numbers in expansion/pop/predecessor/schedule/update fields are merely ample software ceilings, never equal effort or matched CPU. The four diagnostic cells name intentional caps and different publication/availability effects before execution; do not relabel them as complete or drop them after inspection.

## Why compact receipts need a separate parent control

F1 deliberately returns no live forest, parent maps or wire bytes. Same counts/status/digest flags cannot establish canonical parent identity. Alongside each F1 call, a test-local independent caller replays that exact compiled arm through public build/refresh/repair/prefix APIs with its own active origin and occurrence ledger. It retains raw results only inside the test to reconcile every compact row/proposal digest/load delta/status/work against F1 and inspect parents. This extra execution, hashing, M2 and verifier work is **reference/validation overhead**, not part of the arm's reported Source work and not a performance sample. No shadow result repairs/retries/informs an arm.

At every initial/round construction, compute an unbounded-within-small-fixture canonical parent reference using a separately written raw-row sorted FIFO BFS, plus the public full builder with the plan's full-control budget. Reference projection handles directed y→x witness semantics, explicit any-live/reciprocal, current live endpoints, supplied snapshot roots/removal, root score exemption and intermediary-only qualifying gate. Parent comparison uses sorted root/subject/distance/parent rows, not originRoot/reference/config/stats. Complete-equivalent constructions must contain every current eligible root with exact canonical rows in all arms.

For bounded cells, every published row must agree with the complete canonical row for that root/subject and remain parent-closed/current-role/hop valid. Builder/E1 may retain canonical partial prefixes. E2 retained roots must be **whole settled canonical trees**; an aborted root has no map. Complete:true always requires all full reference roots/rows. An unavailable construction supplies no parent reference claim; do not substitute empty parents for unknown availability. Source reports/counters, retired entries and explicit origin/current capture handling remain the existing contracts'.

## Exact cross-arm query projections

Whole F1 rows, proposalDigest, serialized proposal bytes, forest reference/config/build statistics and maintenance requests intentionally differ. Do **not** assert those hashes or lengths equal, strip all metadata wholesale, or call their difference a query behavior change. F1 proposalDigest remains an exact per-arm replay/corruption check against that arm's shadow caller, not a cross-arm semantic key.

For complete-equivalent cells compare called; active current viewRoot/policyId/epoch/complete/eligibleRoots/retainedRoots/treeNodes; result status/reason/feasible/required/coverage/wireDigest/wireBytes/verification; work.proposal and work.prefix; accounting loadRowsBuilt/routeRowsFolded/selectedPeersFolded; loadDelta and cumulative final load rows/totals. Exclude accounting.proposalBytesHashed and forest construction references only. Query budgets and complete canonical trees make these semantic/counter projections identical even though provenance hashes differ. Source positive wires must independently pass M1/ref2 under the requested current capture; do not mistake a digest for a certificate.

Separately compare **phase1 frontier** where both calls actually reached it and current facts/pools/query budgets/pre-query L match. Raw projection is prefix.prefixes; prefix.routes including prefix/poolId/queryId/selected/stats; prefix.stats queued/expanded/maxPending/neighborTrials/scoreReads/routeCalls/generators/draws/routedPeers/missingPools/omittedNeighbors; and coverage prefixLimit/expansionLimit/branchLimit/prefixDepthLimit/poolUnavailable. Exclude endpointChecks/duplicatePaths and treeLookupLimit: phase2 can change them when different retained trees/candidate budgets cause different joins/early stops. A null coverage is no frontier execution, not an empty completed frontier. Equal frontiers imply the same actual selected occurrences, not equal consumed work or accepted family.

Bounded-diagnostic arms need not have equal tree inventory, query statuses, phase2 counters or called flags. Availability differences can legitimately diverge later L and best-of-two choices; do not force common loads externally, reset ledgers or claim unconditional unrelated-query invariance. Compare a phase1 pair only under the stated equal-state preconditions; otherwise emit a named not-comparable reason in test diagnostics and retain the case. No missing/partial/unavailable arm is removed from the requested cell/query count.

## Oracle truth, misses and mechanical stops

For each requested logical query, call the existing full-capture M2 with the plan's explicit budget, independently of advisory status. Identical context/view/epoch/oracle-budget calls may share one result; query IDs/routing modes are not M2 inputs. Count computed/reused reference calls separately. Never raise a cap, change a fixture or rerun under a favorable seed to obtain a negative/positive. Preserve found/infeasible/censored/unavailable and feasible true/false/null; censored/unavailable is not a reference negative. M2 positives also pass both verifiers. Separate raw simple-family enumeration on the tiny fixtures is allowed as an additional control, not an unbounded flow replacement.

Classify Source found as certified-positive; nonpositive with M2 found as confirmed-advisory-miss (retain Source resource/pruning/missing reason); nonpositive with M2 infeasible as reference-negative/advisory-unknown; M2 censored as reference-unknown; M2 unavailable as reference-unavailable. A Source positive with M2 unknown may still be a valid lower bound; a Source positive with a known negative is a contradiction, not two votes to average. The intentional D2 single-tree miss is retained evidence, not a kill or global no-path. Zero known-positive references gives an undefined/null miss fraction; do not fabricate0 or pool incompatible contexts into a general rejection rate.

Mechanical acceptance is zero-tolerance: invalid positive/primary-ref2 disagreement or positive-versus-known-negative contradiction; stale/noncanonical/invalid published rows or E2 partial publication; incomplete roots labeled complete; complete-equivalent semantic/frontier/load drift; shadow/F1 receipt/counter mismatch; unknown-to-negative coercion, omitted requested rows or untyped aggregation of unlike work all fail the test and stop dependent interpretation. These are CI conformance assertions, **not scientific X1/X2/Y2/Z kills**. Preserve the failing fixture/assertion/status; fix/re-scope through a separately documented contract change, never weaken expectations or choose the best run.
