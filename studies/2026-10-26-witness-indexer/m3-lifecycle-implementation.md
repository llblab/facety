## State and availability are separate

A concrete sequence on supplied old/absent frames illustrates the implemented profile:

1. Build old at epoch3; query tick0 obtains/retains a positive through G.
2. Refresh against a same-namespace capture lacking the requested snapshot: called maintenance clears active, not cache or native lastTick.
3. Query old at declared tick2: retained row is unavailable/forest-missing/source uncalled, no probe/advice/fallback, no native clock/sweep. This is an operational skip, not proof the cached packet could not serve.
4. Explicit build old with maxTreeNodes0 creates usable censored local advice. Query tick3 can hit the still-current cache and skip C4/finish. No hidden recovery build is invented.

The actual native clock only advances on called G admissions (one on hit, two on miss), never maintenance, notices or stats reads. Expired-relative-to-a-skipped-declared-tick entries may remain physically retained: finalCache reports actual inventory, not a validity promise. Legacy builder snapshot-only availability versus refresh/repair grace checks remains unchanged. Available censored forests remain active; uncalled maintenance cannot restore a missing index. Runtime active root/policy/epoch must match the nonexecuting symbolic trace.

Querying a changed current capture does not replace the forest's true construction/current-equivalence origin; later maintenance receives that tracked origin. Explicit policy/epoch/reset/rebuild does not flush old-context cache keys. Notices may evict valid proofs, be missing/spurious/duplicated or name unknown256-byte IDs; they never change canonical facts, active index or query clock. Full-current G verification still rejects invalid cached packets without notices. No automatic delta or notice generation exists.
