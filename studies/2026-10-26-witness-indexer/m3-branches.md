## Exact inputs and candidate universe

Forest/current view must be locally constructed; policy IDs must match. Query is exact `{epoch,maxCandidates,maxPackingSteps,maxBranches,maxTreeLookups}`. Existing epoch/candidate/packing domains remain; maxBranches is0..64 and maxTreeLookups0..65536, explicit software budgets, not protocol quotas. Advice is exact `{pool,routing}`; routing is exact `{seed,queryId,step,mode,loads}`. A count-zero M3-C1 preflight validates/copies these data without draws, before availability checks. The actual routing call derives domain/subject from the trusted witness context and viewId/epoch from the supplied current capture/query, start0/count=maxBranches. Caller labels cannot override those bindings. Supplied pool score/load remains advisory; live Standing/anchor selection is not implemented.

Filter retained pool peers against the current subject-first projected neighbors of U, using the capture's explicit directed/any-live/reciprocal semantics, and exclude U itself before routing. Do not refill below retained top-M or invent unknown scores. Loads still cover the entire retained pool, including excluded peers. Current filtering preserves the existing pool hash/key policy; exclusion changes are deliberate input changes, not a new generator layout. No load is incremented or work reserved. Preflight and actual routing/input/neighbor preparation costs are separate from tree lookups.

Candidate order is base U→anchor tree paths first, in the forest's anchor order, then each routed peer V in route order crossed with those same anchors: prepend U to the stored V→anchor path. A root's [V] path thus supplies a genuine one-edge U→V candidate, not zero-hop self support. This enumerates only zero or one explicit next-hop followed by one retained tree path. It neither explores arbitrary depth nor solves the whole public hop-bounded graph.

Each attempted tree retrieval consumes one maxTreeLookups unit, including null/zero-hop results. Each emitted positive-length candidate consumes one maxCandidates unit before simplicity/hop/current-policy rejection or deduplication. Full validation checks U-first, simple/within-r, current terminal membership/removal, every current projected edge and optional intermediate-only score. Terminals and U remain score-exempt; removed anchors may still be unshared transit if ordinary vertex/edge/score policy permits. Valid candidates deduplicate by exact vertex array before bounded exact D-packing. Endpoints participate in non-U family conflicts, so no terminal/transit reuse or duplicate-terminal inflation is introduced. M1 canonical encoding and both independent M1 verifiers own final positive acceptance.

## Results, budgets and completeness

The result retains the proposal envelope and adds a branch reference, normalized route evidence and branch-specific work/coverage metadata. Existing fields retain meaning: found has feasible:true plus a canonical dual-verified wire; every nonpositive status has feasible:null and no witness. Bad host configuration throws, not a search miss. Unavailable epochs/forests return unavailable after bounded data preflight, without route draws or tree retrievals.

Any valid found family may return after incomplete forest/build/candidate/branch/lookup exploration. A negative packing result with exhausted packing/candidate/lookup budgets is censored; if fewer than all eligible retained peers were routed because maxBranches is too small, it is branch-limit censored. If a route returns partial only because fewer eligible peers exist than requested, all retained peers were covered: this alone is not censoring. An incomplete forest without a positive remains censored. Otherwise return miss, never infeasible, even if all retained candidates and packings were examined. Top-M omissions, unknown scores, unavailable tree alternatives and deeper branch requirements prevent global completeness.

First hop and the entire spliced path are rechecked against the current capture even with a matching old root. Stale trees may still supply valid current paths; current edge/score/removal changes can only remove stale candidates, not authorize them. A changed capture/root is not authenticated freshness or atomic Model permission. Poisoning scores/load/omissions affects availability and costs only; exact M2 full-capture fallback is separately budgeted in the existing cache pipeline. This helper does not invoke fallback implicitly.
