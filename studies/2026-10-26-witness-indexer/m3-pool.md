## Boundary and API

`src/path-witness-pool.mjs` owns `createPathWitnessPool`, `routePathWitnessPool`, `PATH_POOL_LIMITS` and `PATH_POOL_RANDOMNESS`. It depends only on Node crypto and the existing `Random`/`RANDOM_GENERATOR`, not Model, the experiment dispatcher, graph/state accessors, trees, caches or either verifier. Later candidate-search composition must separately filter/check current projected edges, simple paths, terminal/intermediary semantics, hop and score policy, exact family compatibility and both verifiers. No pool or route result is proof of feasibility or infeasibility; there is no accepted/feasible/witness field. A copied local pool object is refused, but local branding is not authentication.

`createPathWitnessPool({metric,maxPoolSize,candidates})` accepts exact plain data. Metric labels are `supplied-synthetic/v1`, `supplied-xp/v1` or `supplied-standing/v1`: caller-supplied provenance labels, not a definition, derivation, endorsement or authenticity check for XP/Standing. Rows are exact `{id,score}`; score is null (unknown, omitted from ranking) or a nonnegative safe integer including zero. Duplicate IDs, negative zero, accessors, holes, symbols, extra fields, coercions and malformed Unicode are rejected. Null is not zero. Sort known scores descending, then unsigned UTF-8 ID order; retain at most explicit M, without filling omitted/unknown rows with fictitious scores. M=0 is an explicit empty-advice software setting, not protocol policy.

The frozen pool exposes only schema, metric, maxPoolSize, retained ranked rows, input/unknown counts and a SHA-256 `id` over `JSON.stringify(['facety-path-pool/v1',metric,M,retainedRows])`. The digest binds retained advice, not omitted rows, global completeness, canonical state, unique people or independent controllers. Input permutation and changes to omitted low-rank/unknown rows that do not change the retained pool do not change its id. No caller-owned mutable array/object is retained.

`routePathWitnessPool(pool,{seed,domain,viewId,epoch,subject,queryId,step,start,count,mode,excluded,loads})` requires every field explicitly. No ambient seed, clock, counter, work budget or load is invented. Text fields are nonempty well-formed Unicode, viewId is an untrusted caller-supplied provenance label, and epoch/step/start/count are nonnegative safe integers. Count is bounded and the last ordinal must be safe. Modes are `uniform` and `best-of-two`. Excluded IDs are normalized to a sorted set after raw bounds; IDs outside the retained pool are harmless. Subject itself is never a next-hop candidate. These exclusions do not refill below top-M.

Uniform requires `loads:null` and makes no load observations. Best-of-two requires exact `{id,load}` rows for every retained peer, including excluded peers, with no duplicates, unknown IDs or missing load. Load is a nonnegative safe integer supplied as a frozen logical workload snapshot: it is not global admission capacity, financial cost, verified independence, queue truth or canonical liveness. The primitive never increments/decrements load or schedules/reserves work. Callers account actual attempts/completions/cancellations separately and explicitly refresh the snapshot. The same snapshot across a batched call and equivalent sequential calls yields the same choices; changing load intentionally may change advice.

## Key layout, sampling and prefix controls

The new standalone policy is **`path-pool-keyed/v1`**, with the unchanged existing generator **`sha256-xoshiro128starstar-v2`**. It is research routing randomness, not cryptographic randomness or a replacement for any existing decision/observation/experiment manifest. Every selected route ordinal creates its own `Random` seeded by this exact JSON array:

```text
[policy,seed,domain,viewId,epoch,subject,queryId,step,ordinal,mode,pool.id]
ordinal = start + localSelectionIndex
```

Count, mutable stream offsets, inspection, other queries and later ordinals are not in the key. Candidate order is retained rank order with self/excluded/previously selected IDs removed. Each nonempty ordinal draws one uniform index via existing Random.int; best-of-two draws a second distinct index by indexing the first-excluded ordered list when at least two peers remain. Choose lower supplied load; equal load chooses unsigned UTF-8 ID order. Only the winner is removed; the losing sampled peer remains eligible. Uniform's selected peers are uniform without replacement up to the existing finite-precision generator/index mapping, not cryptographic or exact real-valued randomness. Best-of-two winners are deliberately not uniform.

A request for k choices has the same prefix as a larger request on the same pool/query/load snapshot. A split call preserves that sequence only when start advances by the number already selected and exclusions include those earlier winners; it is not an implicit retry counter. Repeating a logical request replays the same advice without spending work. Other queries, inspection and future actions consume no shared random state. Same ordinal with changed candidate membership/load/provenance is a changed input, not a promise of the same result.

Results bind the immutable pool, normalized query, generator/policy, chosen IDs, per-ordinal sampled peers/winner and logical work counts. Full count yields `routed/ok`; exhaustion yields `partial/pool-exhausted`, including an empty pool. A complete empty count is routed, not a successful membership test. Neither partial advice nor a pruned pool can establish no path. Separate full-view M2 fallback remains necessary in future witness assembly.

Load telemetry is null for uniform, otherwise reports the declared raw snapshot, exact decimal total, maximum and Herfindahl concentration over that snapshot. All-zero total has undefined concentration (null), not zero inequality. BigInt aggregates avoid safe-integer overflow; the displayed Herfindahl is a floating approximation to the exact integer sum-of-squares ratio. This is input telemetry, not measured load balancing, human effort, speed or capacity evidence.

## Bounds and validation before stronger claims

Software bounds: raw candidates/exclusions <=4096, M/count <=64, ID/domain/view/query/subject text <=256 UTF-8 bytes, seed <=1024 bytes; integer score/load/epoch/step/start <=Number.MAX_SAFE_INTEGER. Raw arrays are bounded before filtering/deduplication. No large implicit expansion or user callback occurs. Creation scans/copies bounded input and sorts O(n log n), retains O(M) ranked state; routing scans/copies the explicitly supplied exclusions/loads and uses at most M*candidate-selection scans, one new generator and <=2 draws per selected peer. SHA-256/JSON/UTF-8 work, temporary maps/arrays and immutable result construction are separate costs; no O(k*r), speedup or network-scaling claim applies to this helper.

Focused controls must cover independent literal key/sampling reconstruction, top-M/UTF-8/null/duplicate/zero semantics, permutation invariance, both modes and ties, no replacement including loser retention, explicit loads/HHI/large sums, exhaustion, all numeric/text/array/schema bounds, frozen isolated inputs/results, prefix/split replay and inert inspection/unrelated-query/future-action invariance. Graph composition controls must still use current M1/ref2 certificates and M2 before inferring anything about witness safety/completeness. This slice returns no witness and makes no positive path claim; tree misses and the existing exact fallback remain unchanged. No dataset, reserved confirmation label, E1–E8 study/benchmark, population attack probability or master G1 pass is authorized.
