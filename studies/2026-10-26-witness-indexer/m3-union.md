## Extraction order, role gates and bounded work

Zero-hop seeds never count witness support.

Run subject-side ball first, then anchor-side ball, then retained-tree rows. Subject FIFO starts U; anchor FIFO starts admitted current roots in canonical order. Maintain separate per-side distance/visited maps; already retained is not already visited on both sides. Each side uses global vertex visited for discovery because it extracts an **edge union**, not a simple-path catalogue. Crucially, inspect/admit every tried current arc even when the neighbor was already discovered; keeping only first-parent edges would lose alternatives. A newly discovered endpoint is queued only after its connecting arc was successfully admitted. No repeat phase, repair/relaxation or hidden retry occurs.

Subject root U is score-exempt. Expanding any other subject-side vertex requires its known qualifying score when enabled, even if it is an eligible anchor: a low-score anchor may terminate a path but cannot be an intermediary of a longer one. Anchor-side current seeds are exempt roots; other vertices need the qualifying score. Do not expand U as anchor-side transit. Removed anchors are not seeds/terminals but may transit when the ordinary score/edge policy allows. Individual retained edges have no fixed terminal/transit type; M2/full witness roles decide that later.

On each actual queue pop, apply the role/score stops first, then radius checks. Score stops are policy gates, not resource exhaustion. Each current neighbor trial charges maxBallTrials before visited/admission rejection, shared across both balls. Exact-last exhaustion without another needed trial does not censor by itself. FIFO storage is bounded by live vertices per side, not an unbounded per-pop log.

For a proposed directed arc/pair, first check all missing endpoint slots, then all missing arc slots. Logical retained space is bounded, not all cumulative allocations or process RSS.
